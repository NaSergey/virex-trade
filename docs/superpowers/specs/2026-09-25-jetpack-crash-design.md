# Джетпак — crash-игра на монеты

Дата: 2026-09-25. Запрос владельца: страница игры `/games/jetpack`, одна игра на всех —
без турниров, столов и комнат; механика классическая; заходит и играет сколько угодно
человек.

## Механика

- **Раунд один на всех.** Окно ставок → взлёт: множитель растёт от 1.00x → в случайный
  момент ракета взрывается. Кто успел забрать — получает `ставка × множитель`, кто нет —
  теряет ставку. Раунды идут подряд, пока на странице хоть кто-то есть.
- **Одна ставка на раунд** (решение владельца), только в окне ставок. Отменить нельзя,
  поставить на следующий раунд во время полёта — нельзя: зашедший посреди полёта ждёт
  окна.
- **Забрать** — кнопка во время полёта. **Автовывод** — необязательный множитель при
  ставке (1.01–1000.00x): сервер забирает сам, ровно на нём, если ракета до него
  долетела. Ручной вывод раньше автовывода — законный случай.
- **Против заведения, край 1 %** (решение владельца). Точка краша —
  `max(1.00, floor(99 / (1 − r)) / 100)`, `r` — криптослучайное в [0, 1): шанс дожить до
  `x` равен `0.99 / x`, и матожидание любой цели ровно 0.99 ставки. Следствие формулы:
  около 2 % раундов взрываются на старте (1.00x) — это и есть край на низких целях, а не
  отдельное правило. Потолок — 1000x: раунд длиннее полутора минут не нужен.
- Монеты печатаются и сгорают, как у блэкджека: выигрыш платит заведение. Вывода монет
  нет, поэтому заведение ничем не рискует.
- Ставка 1–10 000 монет, целые. Выигрыш — `floor(ставка × множитель)`: монеты целые.
- XP за джетпак не начисляется (как у блэкджека).

## Время и числа

- Множитель — функция времени полёта: `m(t) = floor(100 · e^(k·t)) / 100`,
  `k = 0.00008 /мс` (2x — через 8.7 с, 10x — 29 с, 100x — 58 с, 1000x — 86 с).
- Окно ставок — 7 с, пауза с показом краша — 3 с.
- Множители хранятся и сравниваются **в сотых, целыми** (`x100`): 2.35x — это 235. Та же
  причина, что у сумм донатов в минимальных единицах: сравнение «успел ли» должно быть
  точным.
- **`k` едет клиенту в виде**, а не повторяется константой во фронте: вторая копия
  формулы разошлась бы с первой при первой правке темпа.

## Сервер — `backend/src/jetpack`

- `jetpack.ts` — чистые функции: точка краша из `r`, `m(t)`, время до множителя,
  выигрыш. `jetpack.config.ts` — константы. `jetpack-view.ts` — единственное место,
  решающее, что видно.
- `JetpackService` — рантайм раунда **в памяти процесса `api`**, как раздача покера:
  отсюда то же требование — `api` остаётся одним процессом. Все операции (ставка, вывод,
  взлёт, краш, автовывод) — через одну очередь (`exclusive`).
- **Цикл спит, когда смотреть некому.** После паузы краша сервер смотрит, есть ли
  сокеты в комнате `jetpack`; нет — раунд не открывается, таймеров нет. Будит его
  открытие страницы (`GET /api/jetpack`), как открытие стола будит раздачу покера. Уже
  идущий раунд доигрывается всегда — ставки в нём живые.
- **Точка краша вытягивается на взлёте** и до краша существует только в памяти: ни в
  виде, ни в базе её нет, пока ракета летит.
- **«Успел ли» решает время прихода запроса**, а не время его обработки: момент
  фиксируется до постановки в очередь. Краш — тоже элемент очереди, поставленный
  таймером ровно в момент краша, поэтому все выводы, пришедшие раньше, разбираются
  раньше него (очередь FIFO). Множитель вывода — `min(m(время прихода), автовывод)`.
- **Автовывод не зависит от точности таймера.** Таймер на каждую цель автовывода
  заводится на момент её достижения — тогда вывод виден всем вовремя. Если таймер
  опоздал и краш наступил раньше, краш сам платит всем, у кого автовывод ≤ точки краша.
  Выигрыш определяется правилом, а не тем, какой колбэк сработал первым.
- Ставки других игроков видны с именами (сумма, множитель вывода, выигрыш), их цель
  автовывода — нет, пока не сработала. Свою строку клиент узнаёт из персонального вида
  (`emitPersonal`), а не по userId.
- Рассылка вида — не чаще раза в 100 мс (ставки и выводы идут пачками). Вид несёт
  серверное время, поэтому задержка рассылки не сбивает отсчёт у клиента.

### Деньги

- **Ставка** — одна транзакция: списание с CAS (`coins.charge`, `JETPACK_BET`,
  `refId` = id раунда) и строка `JetpackBet`. Уникальный ключ `(roundId, userId)` и ключ
  журнала монет держат «одну ставку на раунд» и в гонке двух вкладок.
- **Вывод** — одна транзакция: `updateMany` строки ставки с условием
  `cashoutX100: null` (compare-and-set) и начисление `JETPACK_WIN`. Двойной клик второй
  раз ничего не найдёт.
- **Краш** — строка раунда получает точку краша и `finishedAt` условным `updateMany`
  (`finishedAt: null`); проигранные ставки уже списаны, двигать нечего.
- **Раунд, прерванный перезапуском** (`finishedAt: null` при старте `api`), отменяется:
  ставкам без вывода возвращается сумма (`JETPACK_REFUND`), выведенные уже оплачены.
  Тот же принцип, что у раздач столов: банк теряется, деньги — нет.

### Модель

```prisma
model JetpackRound {
  id         String    @id @default(uuid())
  createdAt  DateTime  @default(now())   // открылось окно ставок
  crashX100  Int?                        // пишется только на краше
  finishedAt DateTime?
  voided     Boolean   @default(false)   // прерван перезапуском, ставки возвращены
  bets       JetpackBet[]
  @@index([finishedAt])
}

model JetpackBet {
  id          String   @id @default(uuid())
  roundId     String
  userId      String
  amount      Int
  autoX100    Int?
  cashoutX100 Int?
  payout      Int?
  createdAt   DateTime @default(now())
  @@unique([roundId, userId])
}
```

Каскад от раунда и пользователя. Раунд пишется, только когда цикл не спит, — пустые
раунды без зрителей базу не засоряют. История на экране — последние 20 завершённых
раундов, при первом пробуждении читается из базы.

### API

- `GET /api/jetpack` — вид (и пробуждение цикла).
- `POST /api/jetpack/bet` `{ amount, autoCashout? }` — `autoCashout` числом с двумя
  знаками.
- `POST /api/jetpack/cashout`.
- Ставка и вывод отвечают свежим видом: кнопка не ждёт рассылки, чтобы узнать, что
  ставка принята.
- Ошибки: `JETPACK_NOT_BETTING`, `JETPACK_ALREADY_BET`, `JETPACK_BAD_BET`,
  `JETPACK_NO_BET`, `JETPACK_NOT_FLYING`, `JETPACK_TOO_LATE`, `INSUFFICIENT_COINS`.
- Сокет — тот же канал `/games`, комната `jetpack` (`join_table` с этим именем —
  подписка, не посадка), событие `jetpack_state`.

## Фронт — `/games/jetpack`, `views/jetpack`

- Экран — ровно один, без прокрутки на десктопе (как стол): полоса истории сверху,
  сцена полёта, под ней панель ставки, справа — ставки раунда. На телефоне колонки
  уходят вниз, прокрутка допустима. Поле тёмное, как весь раздел; акцент —
  `--g-a-purple`.
- **Сцена — от земли до космоса, камера за ракетой** (решения владельца 2026-09-25:
  график с кривой, как у Bustabit, не давал ощущения подъёма; затем — совместить
  расположение ракеты прошлого графика и камеру, начать с земли).
  - **Взлёт:** ракета стоит на площадке вертикально, с площадки валит дым, и по
    дуге гравитационного разворота она уходит вправо-вверх до своей точки кадра
    (68 % ширины, 40 % высоты). Наклон растёт монотонно от 0° до курса 62°, а
    положение — интеграл наклона: нос всегда смотрит туда, куда ракета летит.
    Мир на взлёте стоит — видно, как ракета отрывается от земли.
  - **Дальше камера ведёт ракету по курсу:** ракета держится в точке кадра, мир
    уходит вниз-влево с параллаксом — хребет на закате и город, облака закатного
    неба (передние — над ракетой, она летит сквозь них), потом небо темнеет,
    проявляются звёзды и туманность. Планеты нет — снята владельцем.
  - **Земля — плоский неон по референсу владельца** (ночной космодром): ночное небо
    с разноцветными звёздами и луной, пологие холмы в сиреневой дымке, слева —
    ангар с антеннами, справа — корпус управления с неоновыми полосами окон,
    радаром (луч медленно качается) и белой решётчатой антенной; ракета стоит
    прямо на земле (плита под ней снята), слева от неё — вышка обслуживания со
    стрелой к борту, по сторонам две тонкие радиомачты с розовым верхом и
    мигающими огнями; по линии земли — забор; на переднем плане — лужицы
    (неровные бирюзовые капли с бликом). Луна садится за холмы вместе с
    горизонтом: почти неподвижная, она читалась летящей за ракетой. Стрела вышки
    держит ракету за борт и на старте отходит. Огня на площадке нет: двигатель
    зажигается на старте — факел вырастает от сопла, вспыхивает свет под
    соплом, валит дым. Башня обслуживания с кабель-мачтой, прожекторы, баки, пьедестал,
    неоновый пол-сетка, город и закатное солнце стояли и сняты: «слишком много
    элементов» (владелец).
  - **Высота — функция множителя:** `alt(m) = P·(√m − 1)`, `P` = 2.4 высоты поля.
    Скорость подъёма `∝ √m` — растёт вместе с множителем, но не взрывается, как
    сам множитель. Метка `x` проходит мимо сопла ровно тогда, когда на табло `x`.
    Облака каждого слоя стоят на пути ракеты с поправкой на параллакс слоя.
  - **Ракета — та же, что на карточке, целиком:** корпус, ореол по силуэту, пламя со
    всеми слоями и форсаж — `shared/ui/rocket.tsx`; сборка карточки после переноса
    обязана дать ту же разметку. Стабилизаторы в игре симметричные (`symmetric`):
    ракета стоит на площадке прямо, и ракурс снимка карточки (правый крупнее)
    читался кривой ракетой. Карточка остаётся с ракурсом.
- **Кадр полёта — в DOM, не через состояние React:** множитель, положение ракеты,
  сдвиг мира и слоёв звёзд обновляются в `requestAnimationFrame` напрямую, как перебор
  чисел на карточке. Иначе каждый кадр перерисовывал бы весь экран. Всё движущееся —
  HTML-слои с `transform`/`opacity`, внутри их SVG ничего не анимируется (правило
  сцен витрины). Звёзды — CSS-узор слоя, сдвиг по модулю плитки: слой не кончается.
- Окно ставок — отсчёт до взлёта; краш — вспышка на месте ракеты, число краснеет,
  «Взорвался на 2.35x».
- Панель ставки: сумма (быстрые ½ и ×2), автовывод переключателем и полем, одна
  главная кнопка по состоянию: «Поставить» → «Ставка принята» → «Забрать N» (N растёт
  с множителем) → итог раунда.
- Сокет — общий код рукопожатия выносится из `useTableSocket` в
  `shared/api/games-socket.ts`: путь, слэш и обновление токена не должны жить в двух
  копиях.
- `model/games.ts`: у джетпака `available: true`.

## Проверка

- Юниты: чистые функции (распределение краша по фиксированным `r`, `m(t)` и обратная
  к ней, округление выигрыша), вид, расчёт кадра на фронте.
- Сквозной прогон двумя тестовыми пользователями (REST + socket.io напрямую в API): ставка
  обоих → один забирает руками, у другого автовывод; баланс и журнал монет сходятся;
  вывод после краша отклонён; перезапуск посреди полёта возвращает ставку без вывода.

## Вне задачи

Проверяемая честность (hash-цепочка раундов), ставка на следующий раунд во время
полёта, авто-ставка, чат, звук, XP.
