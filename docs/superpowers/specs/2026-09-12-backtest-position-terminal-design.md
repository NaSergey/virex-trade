# Бектест: открытая позиция как в реальном терминале (без хеджа)

## Контекст и что не входит в этот проект

Панель ордера (`OrderPanel.tsx`) сейчас при открытой сделке превращается в форму
управления позицией (вход/PnL/стоп/тейк/«Применить»/«Закрыть»). Это ломает две вещи:
слайдер стопа не сужен на верную сторону, когда направление уже зафиксировано (можно
визуально утащить стоп на «неправильную» сторону цены при открытом лонге — реально он
не сохранится, `checkLevels` отклонит на «Применить», но выглядит как баг), и панель в
принципе перестаёт быть «панелью открытия» — превращается в другой инструмент по факту
состояния.

Договорились одним заходом сделать три вещи:

1. Панель ордера **никогда не смотрит на то, открыта ли сделка** — ни одной ветки.
2. **Плечо** — реальный параметр (1–100×), влияет на маржу и на ликвидацию.
3. **Добор позиции по рынку** — кнопки Лонг/Шорт при уже открытой сделке той же
   стороны увеличивают её, а не блокируются молча.

**Не входит:** одновременно открытые лонг и шорт (хедж-режим) и частичное закрытие
лимитками. Оба требуют менять инвариант «одна открытая сделка на сессию» (он записан
прямо в схеме: `BacktestTrade` — «Открытая — это сделка с пустым exitTime; отдельной
„позиции“ нет») и логику прокрутки (`useReplay`, `lib/fills.ts`, `BacktestService`).
Это отдельные, более крупные проекты со своей спекой на движок; здесь — только
однопозиционная модель, дополненная плечом и добором.

## Что остаётся без изменений

- `useReplay`, `lib/fills.ts`, `advanceTo` — сделка по-прежнему одна на сессию,
  проверка стопа/тейка построчно на минутках не меняется.
- Драг уровня прямо по графику (`onDragLevel`, `applyStopChange`) — работает как
  сейчас, сохраняется по отпусканию.
- Модель PnL/комиссий/R (`tradeResult`, `positionSize`) — не трогаем; плечо не
  участвует в размере позиции (тот по-прежнему риск / дистанция до стопа), только в
  марже и ликвидации.

## Схема данных

`BacktestTrade` получает новое поле:

```prisma
leverage Float // плечо, с которым сделка открыта; 1–100
```

Не nullable: у бектеста нет «сделки без плеча», плечо 1× — тоже плечо, а не
отсутствие поля. Значение фиксируется при открытии и не меняется добором или правкой
стопа/тейка (как на бирже — плечо позиции нельзя перевыставить, пока она открыта, не
закрыв её).

Миграция: `npx prisma migrate dev` в `backend`, после остановки `nest watch`
(генератор падает `EPERM`, если процесс держит движок — см. память
`prisma_generate_eperm_windows`).

## Маржа и ликвидация — упрощённая модель

Точная биржевая маржа (кросс/изолированная, ступени поддерживающей маржи, ADL) не
моделируется — это диагностический тренажёр, а не клон биржи. Формулы:

- `margin = notional / leverage` — сколько депозита занимает позиция.
- `liqPrice`: long — `entry * (1 - 1/leverage)`; short — `entry * (1 + 1/leverage)`.
  Без поддерживающей маржи и комиссий — приближение, но плечо 100× даёт ликвидацию в
  1% от входа, и этого достаточно, чтобы слайдер плеча физически кусался.

Новые чистые функции в `lib/money.ts`:

```ts
export function liquidationPrice(direction: Direction, entry: number, leverage: number): number
export function averageIn(qtyA: number, entryA: number, qtyB: number, entryB: number): number
```

`previewSize` получает параметр `leverage` и вместо справочного
`leverage: notional / balance` возвращает `margin` и `liqPrice`; комментарий
«Плечо справочное: маржа и ликвидация не моделируются» — снимается, он больше не верен.

**Проверка маржи** — при открытии и при доборе: `margin ≤ session.balance`. Отдельного
учёта «занятой позицией маржи» в модели нет (баланс сессии меняется только на PnL
закрытых сделок, как и сейчас) — проверка сравнивает требуемую маржу целиком
(существующая позиция при доборе + добавка) с текущим `balance`, без раздельного
«свободно/в марже». Это огрубление того же рода, что и у ликвидации: для калибровки
плеча как ощущения риска этого достаточно, полноценный margin-ledger — отдельная тема
(она же нужна была бы и для истории баланса, которой в продукте пока вообще нет).

## Бэкенд (`backtest.service.ts`, `backtest.dto.ts`)

- `OpenTradeDto`/`OpenTradeInput` — новое поле `leverage` (`@IsNumber() @Min(1) @Max(100)`).
- `openTrade`: считает `margin = notional / leverage`, отклоняет с
  `BadRequestException` (`code: 'BACKTEST_MARGIN_EXCEEDS_BALANCE'`), если
  `margin > fresh.balance`. Сохраняет `leverage` на сделке.
- Новый метод `addToTrade(userId, tradeId, input: { entryPrice, riskPct })` +
  DTO `AddToTradeDto` (`entryPrice: @IsPositive()`, `riskPct: @Min(0.01) @Max(100)`),
  endpoint `POST trades/:id/add`:
  - Требует открытую сделку (`exitTime: null`), иначе `tradeClosed()`.
  - Считает добавку через существующий `positionSize(balance, riskPct, entryPrice, trade.stopLoss)`.
  - `newQty = trade.qty + addQty`, `newEntry = averageIn(trade.qty, trade.entryPrice, addQty, entryPrice)`,
    `newRiskUsdt = trade.riskUsdt + addRiskUsdt`, `newRiskPct = newRiskUsdt / balance * 100` (справочно).
  - Плечо — то же, что у сделки (`trade.leverage`), не приходит во входных данных.
  - Проверка маржи: `(newQty * newEntry) / trade.leverage ≤ session.balance`.
  - Защитная проверка стороны: `stopOnRightSide(direction, newEntry, trade.stopLoss)`
    (и `takeOnRightSide`, если тейк есть) — если добор загоняет средний вход за стоп,
    отказ (`BACKTEST_STOP_SIDE`/`BACKTEST_TAKE_SIDE`, та же ошибка, что при открытии).
  - Тот же паттерн блокировки/защиты гонки, что у `modifyTrade` (`bumpCursor` +
    `updateMany({ where: { id, exitTime: null } })`).
- `CreateSessionInput`/DTO не меняются этим проектом (плечо не имеет отношения к
  сессии, только к сделке).

## Фронтенд

### `OrderPanel.tsx` — без веток по `openTrade`

Компонент перестаёт принимать `openTrade`, `onApply`, `onClose`, `canClose`. Вместо
`openTrade: BacktestTrade | null` — три примитива от родителя:

```ts
sameDirectionOpen: Direction | null // сторона уже открытой сделки, если она есть
openLeverage: number | null        // плечо открытой сделки — панель его не выбирает, только показывает
disabled: boolean                  // как сейчас
```

Всегда рендерится: баланс, риск (слайдер+поле), **плечо** (новый `Field`, слайдер
1–100 шаг 1, число рядом с подписью — тот же приём, что у риска), стоп, тейк,
предпросмотр размера (монета/USDT/маржа/ликвидация), `Long`/`Short`, «Завершить».

- Слайдер плеча активен, пока `sameDirectionOpen == null`. Если сторона уже
  открыта — слайдер дизейблится и показывает `openLeverage` (плечо позиции нельзя
  перевыставить добором, см. схему выше); `draft` плечо при этом не трогает.
- Кнопки `Long`/`Short`:
  - `sameDirectionOpen == null` — как сейчас, открывают сделку.
  - `sameDirectionOpen === 'long'` — кнопка `Short` дизейблится (хедж не поддержан),
    подпись поясняющая (`hint`, не блокирующая — как у остальных отказов панели);
    кнопка `Long` меняет подпись на «Добрать лонг» и зовёт `onAdd('long')` вместо
    `onOpen('long')`. Зеркально для шорта.
  - Предпросмотр размера/маржи при доборе считается по текущему `draft.risk` тем же
    `previewSize`, но с плечом `openLeverage` (не тем, что на слайдере, — он в этом
    состоянии не влияет).

Это меняет *поведение* кнопок по состоянию (как и раньше — открытая сделка меняла,
что произойдёт по клику), но не меняет *набор и раскладку полей панели* — тот самый
инвариант, который просили не трогать.

### `SessionScreen.tsx`

- Убирается `useEffect`, синкающий `draft.stop`/`draft.take` из `openTrade` —
  черновик панели больше не про открытую сделку, а про следующий ордер.
- `onAdd(direction)` — новый обработчик рядом с `open()`, вызывает `useAddToTrade`.
- Новый компонент `PositionBar` — полноширинная полоса между `SectionHead`
  (таймфрейм) и `.asym.terminal`, рендерится только когда есть открытая сделка.
  `LedgerTable` в один ряд, тот же визуальный язык, что `OpenPositions` (`.now`,
  `row-reveal`, `Money`, классы `dir`/`n`/`pos`/`neg`), но свои колонки — под
  `BacktestTrade`, не под `ExchangePosition`:
  направление · вход (средний, если был добор) · размер (qty + notional) · плечо ·
  сейчас (`replay.price`) · PnL (+R, как сейчас в панели) · «Изменить» · «Закрыть по
  рынку».
  Полей вроде ликвидации-с-биржи, диапазона входа, тегов инлайн — нет: тегами сделка
  размечается после закрытия, в `SessionTrades` снизу, как и сейчас.
  Кнопка «Закрыть по рынку» и связанные с ней `closeManual`/`canClose` переезжают из
  `OrderPanel` в обвязку `PositionBar` (сама логика — `replay.cursor > entryTime`,
  `closeTrade(...)` — не меняется, меняется только то, какой компонент её вызывает).
- Модалка **«Изменить TP/SL»** (`shared/ui/dialog.tsx`: `Dialog`/`DialogHeader`/
  `DialogBody`/`DialogFooter`) — по референсу Bybit, но без вкладок «Вся
  позиция»/«Частичная» (партиалы не входят) и без поясняющего текста-абзаца
  («When the Last Traded Price reaches…» не переносим). Шапка — вход/размер/текущая
  цена (`DialogHeader aside`). Тело — два блока, TP и SL, в каждом: `Input` с ценой и
  `Slider` под ним, подпись — процент/ROI от входа (тот же приём и тот же знак, что
  `stopPct`/`takePct` в панели сейчас, никакого нового расчёта). Подвал —
  Confirm/Cancel. Confirm зовёт тот же `useModifyTrade`, что сейчас у кнопки
  «Применить» — валидация (`checkLevels`) и мутация не меняются, меняется только
  обвязка (модалка вместо инлайн-полей).
- Уровень **ликвидации** на графике — четвёртый вид уровня в `ReplayChart`
  (`kind: 'liq'`), пунктир своим цветом (`var(--loss)` с меньшей насыщенностью или
  отдельный токен — на усмотрение при вёрстке), не перетаскиваемый. Считается из
  `liquidationPrice(direction, entryPrice, leverage)`, показывается только у открытой
  сделки.
- **Маркеры входа на графике для сделок сессии** (пункт из первого запроса,
  подтверждён по смыслу как часть «панели, как обсудили», но не был отдельно
  переспрошен после эскалации до плеча/добора — стоит явно кивнуть при ревью спеки):
  треугольные метки входа/выхода на свечах для уже закрытых сделок сессии, тем же
  приёмом, что `RangeCheckChart.tsx` (`marker()` — стрелка снаружи свечи, подписи
  `t('markerEntry')`/`markerExit`), поверх уже существующих пунктирных линий текущей
  сделки. Если это не нужно сейчас — вычёркиваем одной строкой на ревью, работы на
  отдельную маленькую задачу, не блокирует остальное.

### API-слой (`api/hooks.ts`, `api/types.ts`)

- `BacktestTrade.leverage: number` — новое поле.
- `useOpenTrade` — тело мутации получает `leverage`.
- `useAddToTrade(sessionId)` — новый хук, `POST /api/backtest/trades/:id/add`,
  `onSettled` тот же `refresh`, что у остальных мутаций сделки.

## Тестирование

- `backend/src/backtest/backtest.service.spec.ts` — кейсы: открытие с плечом
  сохраняет `leverage`; открытие с маржой больше баланса отклоняется; `addToTrade`
  считает средний вход и суммарный риск (числовой пример), отклоняет добор без
  открытой сделки и добор с недостаточным балансом.
- `backend/src/backtest/backtest-math.spec.ts` — если `positionSize`/`tradeResult`
  не меняются, новых тестов там не требуется; маржа/ликвидация — чистые функции,
  тесты живут на фронте рядом с остальными (ниже).
- `frontend/.../lib/money.test.ts` — `liquidationPrice` (long/short, несколько
  плечей, включая 100×), `averageIn` (обычный случай, случай с одинаковым qty).
- Ручная проверка сценария добора и модалки — дев-сервер, как и у прошлой панельной
  правки (`docs/superpowers/specs/2026-09-12-backtest-order-panel-terminal-design.md`
  не гоняла билд ради 1–2 файлов; этот проект трогает схему и бэкенд — здесь `next
  build`/полный прогон бэкенд-тестов нужен перед коммитом, не только `tsc`).

## Порядок реализации

1. Схема + миграция (`leverage` на `BacktestTrade`).
2. Бэкенд: DTO, `openTrade` (плечо + проверка маржи), `addToTrade` + эндпоинт, тесты.
3. `lib/money.ts`: `liquidationPrice`, `averageIn`, `previewSize` с плечом, тесты.
4. `OrderPanel.tsx`: плечо в панель, безусловный рендер, состояния кнопок
   Long/Short/добор.
5. `SessionScreen.tsx`: `PositionBar`, модалка «Изменить TP/SL», уровень ликвидации
   на графике, обработчик `onAdd`, снятие синка `draft` от `openTrade`.
6. API-слой (`useAddToTrade`, типы).
7. (Опционально, по итогам ревью спеки) маркеры входа/выхода на графике для
   закрытых сделок сессии.
