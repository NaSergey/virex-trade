# Профиль-дашборд и окна наград

Запрос владельца 2026-10-01: профиль по образцу дашборда игрока (шапка с плитками,
достижения, активность, графики, лента, таблицы справа) — в дизайне продукта;
ежедневная награда и награды сезона — отдельными окнами, красочнее нынешних.

Решения владельца: дашборд — **про игры и сезон** (журнал сделок остаётся на своих
страницах); **достижения есть и выводятся из данных**, не хранятся.

## Что на странице `/profile`

Сетка панелей, разделённых волосяными линейками (структуру держат линейки, а не
карточки — правило продукта). Страница обычная: тема листается, нулевой радиус,
цвет — только краска и её доли. Игровые тона `--g-*` на страницу не выходят.

1. **Шапка** — слот героя с номером уровня (модели героев ещё рисуются — заглушка
   остаётся), имя, «в игре с <даты регистрации>», полоса XP уровня. Плитки: место в
   рейтинге, очки рейтинга, турниров, побед, монеты (баланс). Справа — две кнопки:
   **«Ежедневная награда»** (точка, пока сегодняшняя не забрана) и **«Награды
   сезона»** (число монет, ждущих кнопки). Кнопки открывают окна. Место, очки,
   турниры и победы — строка смотрящего в `/api/tournaments/rating` (строка в
   `rows` или `me`), а не поля `/api/profile`: второго правила очков нет.
2. **Достижения (n/12)** — сетка значков. Получённый — краской, неполученный —
   приглушённый, с прогрессом `value / target` в подсказке.
3. **Активность** — 26 недель × 7 дней, квадратные клетки (радиус нулевой), яркость
   — доля краски по числу действий за день (5 ступеней). Заголовок — действий за
   полгода.
4. **Где играет** — паутинка на пять осей (турниры, бектест, джетпак, покер,
   блэкджек). Значение оси — дней за последние 90, в которые человек играл в эту
   игру; форма нормирована на максимум, подпись — «N дн.». Дни, а не число
   действий: раунд джетпака длится секунды, турнир — часы, и счёт действий
   рисовал бы один джетпак.
5. **Опыт** — линия XP по дням за 90 дней (не накопленный итог сезона: тот
   обнулялся бы на смене квартала, и первые дни сезона график стоял бы пустым);
   крупное число — XP сезона с подписью «XP за сезон», под ним XP за 7 дней и
   неделей раньше.
6. **Баланс монет** — линия баланса на конец дня за 90 дней; крупное число —
   текущий баланс, под ним изменение за 30 дней.
7. **Лента** — 20 последних строк журнала монет: когда, событие (вид строки
   переводится), сумма со знаком, баланс после.
8. **Правая колонка:** **Игры** — строка на игру: сыграно всего, дней за 90,
   последняя игра. **Рейтинг игроков** — тот же блок, что на странице турниров
   (`Rating` переезжает в `widgets/tournament-rating`: теперь он на двух
   страницах), своя строка выделена.

На ≤900px колонки складываются в одну, панели идут в порядке списка.

### Где у столов «итог в монетах»

Итога по игре в таблице нет: у карточных столов строка `GameSeat` удаляется при
уходе, и пара `GAME_BUYIN`/`GAME_CASHOUT` больше не говорит, за каким столом она была.
Колонка, пустая у двух игр из пяти, хуже её отсутствия; общий итог виден на графике
баланса.

## Окна наград

Оба — `tone="game"` (тёмное поле в обеих темах): это и есть «красочнее» — игровое
окно со своим светом, монетами и движением. Цвет свечения окна становится
переменной (`--dlg-glow-rgb`, по умолчанию зелёный турнира): у ежедневной — янтарь
`--g-a-amber`, у сезона — фиолетовый `--g-a-purple`.

**Ежедневная награда** (`features/daily-reward`, `DailyRewardDialog`). Одно окно на
два входа: само всплывает при первом заходе за день (как сейчас) и открывается
кнопкой профиля. Внутри: серия дней («N дней подряд»), семь карточек дня — знак
монеты и сумма; пройденные — с отметкой и притушены, сегодняшняя — крупнее, янтарная
кромка и дыхание света, седьмая — шире, «джекпот» недели. Кнопка «Забрать +N».
После ответа сервера окно не закрывается: монеты разлетаются из карточки дня, она
становится отмеченной, кнопка — «Готово», ниже «Завтра: +M». `DailyWeekRow` из
сущности удаляется — у ряда остаётся один пользователь, окно.

**Награды сезона** (`views/profile/components/SeasonRewardsDialog`). Сезон и срок
(«до 31 декабря» — незабранное сгорает, срок обязан быть рядом с кнопкой), крупный
номер уровня, полоса XP «до уровня N+1 — X XP». Лестница пятидесяти уровней —
горизонтальная лента карточек с прокруткой, при открытии прокручена к текущему
уровню; линия под лентой залита до текущего. Карточка: номер, монеты; забранная —
отметка, готовая — фиолетовая кромка и свет, закрытая — замок и порог XP. Кнопка
«Забрать +N» (одна на всё, как сейчас); после ответа — разлёт монет из готовых
карточек, они становятся забранными.

Движение — CSS, `transform`/`opacity`; под `prefers-reduced-motion` разлёта нет,
состояние меняется сразу.

## Сервер: `GET /api/profile`

Новый модуль `backend/src/profile`, только чтение. Один эндпоинт на всю страницу,
кроме того, что уже приходит своими ключами: Battle Pass (`/api/battlepass`), баланс
(`/api/coins`), рейтинг (`/api/tournaments/rating`).

```ts
{
  since: string;                       // User.createdAt
  activity: { from: string; counts: number[] };     // from — понедельник UTC, ряд кончается сегодня
  games: { id: GameId; played: number; days90: number; lastDay: string | null }[];
  xpSeries: { day: string; xp: number }[];          // XP за каждый из 90 дней
  coinSeries: { day: string; balance: number }[];   // баланс на конец дня, 90 дней
  achievements: { id: AchievementId; earned: boolean; value: number; target: number }[];
  feed: { id: string; at: string; kind: string; delta: number; balanceAfter: number }[];
}
type GameId = 'tournament' | 'backtest' | 'jetpack' | 'poker' | 'blackjack';
```

- **Действие** — одна строка из: участие в турнире (`joinedAt`), своя сессия бектеста
  (без `tournamentId`), ставка джетпака, раздача стола с вкладом человека
  (`contributions ? userId`, завершённая, не `voided`), сделка, размеченная тегом
  (XP-событие `journal.tag`), ежедневная награда. Одним запросом `UNION ALL`,
  сгруппированным по (день UTC, вид) за всё время, — из него выводятся активность,
  игры и счётчики достижений. Раздачи ищутся по ключу JSON без индекса: на нынешних
  объёмах это скан таблицы в десятки миллисекунд; GIN-индекс — когда станет заметно.
- **Ряды графиков** считаются чистыми функциями (`series.ts`): дни без строк несут
  прежнее значение; баланс до первой строки окна — `balanceAfter` последней строки
  до окна, а без неё — `balanceAfter − delta` первой строки (иначе старт колонки,
  1000).
- **Сетка активности кончается сегодняшним днём:** длина ряда и говорит клиенту, где
  «сегодня», — дни после него в последнем столбце он рисует пустыми без своих часов.
- **Лента** сортируется по `createdAt`, затем по `id`: награды сезона за несколько
  уровней пишутся одной транзакцией с одним временем. `id` — ключ строки на клиенте.
- **Счётчики турниров для значков** — те же условия, что у рейтинга (место проставлено,
  турнир `finished`).
- **Достижения** — реестр `achievements.ts` (тот же приём, что реестры XP и
  уведомлений): `id`, `target` и функция факта. Не хранятся: правило — соглашение, и
  сохранённое пришлось бы пересчитывать. Список:

  | id | условие |
  |---|---|
  | `first_tournament` | доиграл турнир |
  | `first_win` | 1-е место в турнире |
  | `champion` | 10 побед в турнирах |
  | `streak_7` | 7 ежедневных наград подряд (лучшая серия за всё время) |
  | `level_10` | 10-й уровень в любом сезоне (`battle_pass_progress`) |
  | `jetpack_x10` | вывод на ×10 и выше |
  | `jetpack_100` | 100 ставок в джетпаке |
  | `poker_100` | 100 раздач покера |
  | `blackjack_100` | 100 раундов блэкджека |
  | `tagger_100` | 100 сделок, размеченных тегом |
  | `backtest_10` | 10 своих сессий бектеста |
  | `rich_10k` | баланс 10 000 монет (максимум `balanceAfter`) |

## Фронт

- `entities/profile` — тип ответа и `useProfile` (ключ `['profile']`; сбрасывается
  вместе с `battlepass` после забора наград — меняются лента и баланс).
- `views/profile/components/` — панели страницы, `SeasonRewardsDialog`; графики —
  своё SVG с приёмом `u = W / boxW`, паутинка и сетка активности — тоже SVG/CSS.
- `features/daily-reward` — `DailyRewardDialog` (окно) и прежний автоматический
  показ, теперь через него.
- `widgets/tournament-rating` — `Rating` со страницы турниров.
- Тексты — `profile.*` в обеих локалях; названия достижений и видов строк журнала
  — по ключу.

## Проверка

Юниты бэкенда (jest): ряды графиков, сетка активности, лучшая серия, реестр
достижений, сборка ответа на подменённых данных. Фронт: `tsc`, eslint, `next build`
(новая страница-раскладка и модуль бэкенда — крупная правка). В браузере не
проверяется — смотрит владелец.
