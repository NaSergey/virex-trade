# Обучение при первом входе: пошаговые туры

Дата: 2026-09-02

## Задача

Человек, впервые зашедший в приложение, не понимает, что перед ним. Разделов пять,
чисел на Обзоре два десятка, а половина ценности продукта держится на ручной разметке
тегами — то есть на действии, которого никто не ждёт и никто не объяснил.

Критерий готовности продукта сформулирован как проход пути: регистрация → ключи →
сделки → первый тег → первый срез, **ни разу не спросив автора**. Обучение обязано
закрывать именно этот путь, а не быть разделом справки.

## Форма

Пошаговый тур с подсветкой: затемнение экрана, «дырка» под объясняемым элементом,
карточка с текстом рядом. Один тур на раздел, плюс приветственные шаги в начале тура
Обзора — первой страницы, куда человек попадает после входа.

Тур раздела запускается **сам, при первом заходе в этот раздел**, и больше не
появляется. Обучение размазано по времени: рассказ про теги приходит тогда, когда
человек открыл «Теги», а не в первую минуту вместе со всем остальным.

Каждый шаг говорит **зачем оно и что с ним делать**, а не «здесь таблица». Это прямое
следствие принципа «система его будет учить»: обучение — поведение продукта.

## Хранение

`localStorage`, **один ключ на все туры** — `virex.tours.seen`, значение списком id через
запятую. Бэкенд не трогается, миграции нет.

Один ключ, а не пять, из-за чтения: `usePersistentValue` — единственный в проекте
безопасный способ читать хранилище прямо в разметке, не расходясь с серверным рендером,
и он работает с одним ключом и примитивом. Пять ключей потребовали бы чтения в эффекте,
а это вспышка карточки у того, кто обучение давно прошёл.

Отсюда же следует, что состояние тура **выводится, а не хранится**: адрес плюс список
пройденных плюс номер шага. Автозапуска как отдельного действия не существует, поэтому
не существует и случая, когда он не сработал или сработал дважды. Уход со страницы
посреди тура просто перестаёт его выводить, пройденным не считая; возврат в раздел
продолжает с того шага, где человек ушёл.

Осознанная расплата: другой браузер, телефон, приватная вкладка или чистка данных —
и туры показываются заново. Для аккаунтного хранения понадобилось бы поле в `User` и
пара эндпоинтов; решено, что цена сейчас выше пользы. Если жалобы появятся —
переезд на сервер меняет только `model/seen.ts`, остальное не знает, где отметка.

## Архитектура

```
frontend/src/features/onboarding/
  index.ts
  model/tours.ts          определения туров: id, маршрут, шаги (якорь + ключ i18n)
  model/seen.ts           формат отметок в localStorage
  model/useAnchorRect.ts  поиск якоря, ожидание, геометрия
  model/OnboardingContext.tsx  вывод активного тура и переходы по шагам
  ui/TourOverlay.tsx      затемнение с дыркой + карточка шага
```

Слой — `features`, не `widgets`: это не блок страницы, а поведение поверх всех.
Провайдер монтируется один раз в `app/(app)/layout.tsx`, внутри `AuthGuard` — без
сессии учить некого.

### Привязка к элементам

Атрибутом `data-tour="..."` на уже существующих узлах. Шаг знает про страницу ровно
одну строку — селектор; ни один компонент страницы не меняет логику и не получает
новых пропсов. Убрать обучение целиком = удалить фичу и снять атрибуты.

### Подсветка

Один `<svg>` на весь вьюпорт, `mask`: белый прямоугольник экрана минус чёрный
прямоугольник по `getBoundingClientRect()` цели (+6px воздуха). Поверх — рамка в один
волос цветом `--major`, чтобы граница выделенного читалась и на светлой теме.

Клик по затемнению ничего не делает: случайный промах мимо кнопки не должен терять
обучение. Закрывают Esc и «Пропустить».

### Карточка

`@radix-ui/react-popover` — новая зависимость, но из семейства, которое уже стоит
(`react-dialog`, `react-tooltip`). Позиционирование у произвольного прямоугольника,
переворот вверх/вниз у края экрана и зажим по горизонтали — его работа; писать эти
сто строк геометрии руками означало бы завести собственный источник ошибок на узких
экранах. Якорь — невидимый `div` с `position: fixed` в координатах цели.

Оформление — своё, классами из `globals.css`, как у диалогов: рамка `--major`, фон
`--ground`, три зоны (счётчик шагов, текст, кнопки). Тёмная и светлая темы работают
сами, потому что цвета берутся переменными.

### Шаг без якоря

Приветствие и вводные фразы якоря не имеют: карточка встаёт по центру экрана, дырки
в затемнении нет. Отдельная ветка рендера, без Popover.

### Пропуск шага, которому нечего показать

Необязательных блоков много: кривой эквити нет, пока нет двух точек; открытых позиций
нет, пока их нет; переточателя бирж нет, когда биржа одна. Отдельных условий для каждого
случая не нужно — **отсутствие якоря и есть условие**.

Проверка идёт в два приёма, и это не дублирование:

1. **В момент нажатия «Далее».** Провайдер сам перешагивает вперёд до ближайшего шага, у
   которого якорь либо не нужен, либо сейчас в документе. К третьему шагу тура страница
   давно догрузилась, поэтому отсутствие узла здесь означает «нечего показывать».
2. **Ожиданием внутри шага** — `MutationObserver` до 3 секунд. Оно закрывает то, чего
   первый приём не видит: первый шаг тура (страница ещё грузится) и узел, который
   появится позже.

Без первого приёма человек, нажав «Далее», смотрел бы на пустое затемнение по три
секунды на каждый отсутствующий блок — а на пустом аккаунте их два подряд.

Ожидание, закончившееся ничем на **первом** шаге, тур пройденным не отмечает: иначе
медленный ответ сервера на странице ключей означал бы, что обучение молча пробежало
свои шаги и записалось пройденным, ни разу не показавшись.

Найденный якорь подводится к центру экрана (`scrollIntoView`), геометрия
пересчитывается на `scroll` и `resize` через `requestAnimationFrame` — событиями,
сведёнными в один кадр, но без отмены уже назначенного: отмена на каждом событии
полностью съедала обновление за время плавной прокрутки.

### Счётчик и кнопки

Счётчик «шаг N из M» считает только показанные шаги — сквозная нумерация прыгала бы с
«4 из 8» на «7 из 8», что на глаз неотличимо от поломки. Знаменатель оптимистичный:
непройденные шаги считаются показываемыми, поэтому он может один раз уменьшиться, но
никогда не растёт.

Подписи кнопок («Далее» против «Готово») определяются **по индексу шага, без обращения к
документу**. Расчёт выполняется при смене адреса, когда новая страница ещё не
отрисована, и заглядывание вперёд давало «дальше ничего нет» на первом же шаге каждого
раздела. Расплата — «Далее» на последнем показанном шаге, если пропущены хвостовые.

### Мобильный

Ниже 640px карточка не летает у элемента, а прилипает листом к низу экрана: у
попапа рядом с целью на такой ширине просто нет места. Подсветка та же.

### Доступность

`Esc` — пропустить, `←`/`→` — шаги, фокус уходит в карточку при появлении шага,
`role="dialog"` + `aria-live="polite"` на тексте, кнопки — обычные `Button` из
`shared/ui`.

## Состав туров

Тексты — в `shared/i18n/messages/{ru,en}.json`, раздел `onboarding`. Тест на паритет
ключей ru/en уже есть и покроет их автоматически.

### `overview` — Обзор

1. **Центр.** Что это за продукт и три ошибки, которые он берётся ловить: вход не по
   системе, слив депозита, долгое держание убыточной сделки.
2. **Рейка разделов** — пять разделов и что в каждом.
3. **Рейка периода** — всё на странице посчитано за него.
4. **Свод** — сколько вышло за период.
5. **Кривая** — как это набиралось; пик и просадка в маргиналии.
6. **Открытые позиции** — единственная заливка на листе.
7. **Журнал сделок** — здесь ставится первый тег, кнопкой в строке. Это то самое
   действие, ради которого всё остальное считается.
8. **Центр.** Что делать дальше: подключить ключи Bybit в Настройках, если ещё не.

### `tags` — Теги

1. **Центр.** Теги — ответ на вопрос «почему я вошёл». Таксономия своя, навязанной нет.
2. **Комбинации** — что с чем встречалось вместе и чем кончилось; создание живёт
   последней строкой таблицы.
3. **Все теги** — по одному. Здесь же обязательная оговорка: **сделка целиком
   засчитывается каждому своему тегу**, строки пересекаются, колонка не суммируется в
   общий PnL.

### `analytics` — Аналитика

1. **Центр.** Лаборатория: задаёте условия и смотрите, чем эта выборка отличается от
   всех ваших сделок.
2. **Условия** — фильтры слева.
3. **Сравнение с базой** — главное число раздела.
4. **Кривая выборки** — как выборка себя вела.

### `market` — Рынок

1. **Центр.** Раздел не про ваши сделки, а про фон, на котором они происходили.
2. **Общий фон рынка.**
3. **Позиционирование** — по инструменту.
4. **Шансы по дням недели** — с выбором глубины истории.

### `settings` — Настройки

1. **Форма ключей.** Ключи только на чтение: права проверяются программно, ключ с
   правом торговли или вывода будет отклонён. Утечка базы означает раскрытую историю
   сделок, а не слитый депозит.
2. **Выбор биржи** (шаг пропускается, когда биржа одна). Реально проверен только
   Bybit — остальные адаптеры живых сделок не видели.

## Перезапуск

В меню профиля (шапка, рядом с языком и выходом) — «Обучение · Пройти заново»: стирает
список пройденных, после чего тур текущего раздела начинается сам. Доступно с любой
страницы, потому что туры идут по всем пяти разделам и вернуть их надо уметь оттуда, где
застрял, а не сходив за этим на страницу ключей.

## Что сознательно не делается

- **Чек-листа онбординга нет.** Обсуждался, отвергнут в пользу туров.
- **Условного запуска по готовности данных нет.** Тур не ждёт, пока подключат ключи;
  пустые блоки просто не имеют якорей и пропускаются.
- **Прогресс не пишется на сервер** (см. «Хранение»).
- **Разбора спорных чисел нет** сверх одной оговорки про PnL по тегам: фандинг,
  таймфрейм и комиссии в туры не выносятся, чтобы шаги не превратились в справочник.

## Проверка

Пройдено на поднятом стеке (Postgres + API + web), на **чистом аккаунте без ключей** —
том самом случае, где половина якорей отсутствует:

- `npx next build`, `npx tsc --noEmit`, `npm run test` (85 тестов, включая паритет
  ключей ru/en), `npm run lint` — обучение ошибок не даёт (две оставшиеся ошибки линта
  в `LocaleProvider` и `analytics/Page` были до этой работы).
- Все пять туров проходятся целиком и отмечаются пройденными:
  Обзор 6 показанных шагов из 8 (кривая и открытые позиции пропущены), Теги 3,
  Аналитика 4, Рынок 4, Настройки 2. Ошибок в консоли нет.
- Перезагрузка страницы туры не повторяет; «Пройти заново» возвращает их.
- Проверены светлая тема и ширина 390px (карточка листом снизу).

Тестовые аккаунты из dev-базы удалены.
