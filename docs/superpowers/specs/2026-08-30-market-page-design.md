# Доделать страницу «Рынок» — дизайн

## Зачем

Бэкенд уже отдаёт пять эндпоинтов `/api/analytics/*`, из них на странице «Рынок»
(`frontend/src/views/market`) используется только один (`market-sentiment`, через
`useMarketSentiment` → `Positioning`) и ещё два — почасовая волатильность и корреляция по дням
недели (свой модуль, `market-events-hooks`). Хуки под остальные четыре (`useMarketData`,
`useFearAndGreed`, `useDeFiTVL`, `useVolatility`) написаны и типизированы, но нигде не
подключены. Плюс нет хука под `/api/analytics/cmc20` вовсе.

## Честность по индексу топ-20

В проекте не задан `CMC_API_KEY` (нет ни в `.env`, ни в `.env.example`) — эндпоинт `cmc20`
всегда идёт по запасному пути: средневзвешенная по капитализации **цена** топ-20 монет
CoinGecko (`AnalyticsService.getCMC20`, ветка без ключа), не официальный продукт
CoinMarketCap. В UI это «Индекс топ-20» без упоминания CMC, со значком-подсказкой (тот же
`Tooltip`, что уже есть у Edge Score), поясняющим, что это средневзвешенная цена, а не «пункты»
биржевого индекса.

## Компоновка

Два новых места на уже существующей странице (без нового раздела в навигации):

1. **`MacroSnapshot`** — новая строка из 4 плиток над `Positioning`, тем же визуальным языком
   (`.coef`/`.coef-v`), что и у неё, только на 4 колонки: Fear & Greed, Капитализация рынка +
   суточное изменение, Индекс топ-20 + изменение (со значком-подсказкой), DeFi TVL. Это фон
   рынка целиком, не привязанный к выбранному инструменту — стоит над своим заголовком
   («Общий фон рынка»), не внутри блока Positioning.
2. **Волатильность инструмента** — четвёртая колонка в уже существующем `.coef` у
   `Positioning` (сейчас там Long/Short, открытый интерес, доля лонгов): та же привязка к
   выбранному инструменту (переключатель BTC/ETH/SOL), заводить второй такой не нужно.
   Подсвечивается красным (`.neg`), когда `elevated: true` — то же условие, что уже красит
   алерт в Telegram.

Каждая цифра — свой независимый запрос со своим скелетоном на месте значения; одна медленная
плитка (DeFiLlama, без кеша на бэкенде) не держит остальные три готовые.

## Данные

Новый хук `useCMC20` в `market/api/hooks.ts`, тем же паттерном, что и четыре соседних —
`apiFetch` + ручная проверка `.ok`, `staleTime`/`refetchInterval` 600 000 мс:

```ts
export interface Cmc20Data {
  index: number;
  change24h: number;
}

export const useCMC20 = () =>
  useQuery({
    queryKey: ['analyticsCmc20'],
    queryFn: async () => {
      const response = await apiFetch('/api/analytics/cmc20', { method: 'GET' });
      if (!response.ok) throw new Error(`HTTP error! status: ${response.status}`);
      return response.json() as Promise<Cmc20Data>;
    },
    staleTime: 600_000,
    refetchInterval: 600_000,
  });
```

Хуки продолжает вызывать `Page.tsx` (data-fetching слой страницы), компоненты остаются
презентационными — тот же принцип, что уже держат `Positioning`/`HourlyVolatility`/
`WeekdayOdds`.

## Загрузка и ошибки

Как везде на странице: `isLoading` → скелетон на месте значения, иначе есть данные → число,
иначе (в т.ч. ошибка внешнего API — `isLoading` уже `false`, `data` ещё `undefined`) → «—» без
отдельного вида под ошибку. В проекте нет отдельной обработки `isError` ни на одном виджете
Обзора или Рынка — новый вид под неё заводить в одиночку не стал.

## Классификация Fear & Greed

`classification` с alternative.me — фиксированный английский набор из пяти значений
(`Extreme Fear`, `Fear`, `Neutral`, `Greed`, `Extreme Greed`). Сопоставление с переводом —
чистая функция `market/lib/fearGreedLabel.ts`, тем же приёмом, что `habitLabel` в
`overview/lib/habit-labels.ts`: перевод получает готовую строку через параметр `t`,
незнакомое значение возвращает как есть (нелокализованная строка лучше пустого места).

## Форматирование чисел

`fmtUsdCompact` (`market/components/SentimentChart.tsx`) сейчас без разряда триллионов —
капитализация всего рынка ($2–3 трлн) попала бы в ветку миллиардов и показалась бы как
«$2340.5 B». Добавляю разряд `>= 1e12 → "$X.X T"`; это расширение уже существующей функции, а
не новая параллельная — ей уже пользуется `Positioning`, выигрывают оба места. Индекс топ-20
(средневзвешенная цена, не капитализация) под этот разряд не попадает — там же используется
`fmtUsdCompact`, без изменений в местах вызова.

Проценты (суточное изменение капитализации и индекса топ-20) — уже существующий
`fmtPctSigned` (`shared/lib/utils/format.ts`), без изменений.

## CSS

`.coef` сейчас жёстко на 3 колонки (`globals.css`). Добавляю модификатор:

```css
.coef-4 { grid-template-columns: repeat(4, 1fr); }
```

Ставится вместе с базовым классом (`className="coef coef-4"`), перекрывает 3-колоночное
правило по порядку следования в файле; мобильная раскладка `.coef` в 1 колонку уже общая для
всех разрядностей и трогать её не нужно — она объявлена позже в файле (внутри media-запроса) и
самостоятельно перекроет обе разрядности на узком экране.

Подпись под значением плитки (словесная классификация Fear & Greed, знак изменения) — новый
класс `.coef-sub` (мелкий, приглушённый), не переиспользую `.foot`: тот держит другие поля
(`max-width: 88ch`, отступ между несколькими сносками подряд) под сноску целой таблицы, не под
плитку в строке коэффициентов.

## Тесты

`fearGreedLabel` — единственная чистая функция в этой задаче, покрывается тестом (все пять
известных значений + запасной случай). Остальное — презентационные компоненты; как и весь
`views/market` (и весь фронтенд-UI проекта), без тестов на сам JSX. Проверка — `tsc --noEmit`,
`vitest run` (parity RU/EN у `messages.test.ts`), `next build`.

## Вне рамок

- `useMarketSentiment`, `useHourlyStats`, `useMarketCorrelation` — уже подключены, не трогаю.
- Настоящий ключ CoinMarketCap не заводится — вне зоны ответственности фронтенда.
- Отдельный вид под ошибку внешнего API — не сейчас, см. «Загрузка и ошибки».
