# Сортировка таблицы «Подходящие сделки» на Аналитике

Дата: 2026-09-07

## Задача

На странице тегов таблица «Все теги» умеет две вещи: поиск по имени и сортировку по
клику на заголовок числовой колонки. У таблицы «Подходящие сделки» на Аналитике
(`TradesTable`, компонент `widgets/trades-table`) нет ни того, ни другого — `LedgerTable`,
на которой она стоит, уже умеет кликабельные заголовки (`sortKey`/`sort`/`onSort`), но
`TradesTable` их не использует вовсе.

Поиска в этой таблице не будет: слева на странице уже стоит панель условий (`LabFilters`)
на тринадцать измерений, включая символ и теги, — она формирует сам список через бэкенд, и
текстовый поиск по нему дублировал бы уже существующий, более полный инструмент. Не
хватает только сортировки уже отобранного списка.

## Область изменения

Только страница Аналитики. `TradesTable` — общий виджет для Аналитики и Обзора
(«Закрытые сделки»); сортировка добавляется как опциональные пропсы (`sort`/`onSort`),
включённые только там, где их передают. На Обзоре они не передаются — там ничего не
меняется, заголовки останутся некликабельными.

## Пагинация — почему сортировка не может жить в самой таблице

`AnalyticsPage` режет список подходящих сделок (до 200 штук, отдаёт `/api/trades/lab`) на
листы по 30 на клиенте (`trades.slice(...)`) и передаёт в `TradesTable` только текущий
лист. Если сортировать внутри `TradesTable`, клик по колонке переставлял бы местами только
30 видимых строк, а не весь список, — на следующем листе оказались бы сделки в прежнем,
несортированном порядке. Поэтому состояние сортировки живёт в `AnalyticsPage`, список
сортируется целиком **до** нарезки на листы, а `TradesTable` становится управляемой извне:
принимает `sort`/`onSort`, сама ничего не переупорядочивает.

## Какие колонки сортируются

Только числовые — тот же принцип, что в `AllTags` («по каким колонкам таблицу можно
отсортировать — только числовые»). На Аналитике таблица работает в сжатом виде
(`compact`), который и так прячет «Выход», «Размер», «В позиции». Из оставшихся видимых
колонок сортируемые: **Закрыта** (`closedAt`, по метке времени), **Вход**
(`avgEntryPrice`), **Диапазон входа** (значение того таймфрейма, что выбран тумблером
слева), **P&L** (`closedPnl`).

- Колонки «Выход», «Размер», «В позиции» тоже получают `sortKey` в определении (на
  случай, если сортировка когда-нибудь понадобится и на Обзоре, где эти колонки не
  прячутся) — но остаются недостижимыми на Аналитике, где `compact` их не рендерит.
- Символ, направление и теги не сортируются — они не числа, и алфавитный порядок символа
  или направления не отвечает ни на один вопрос, ради которого в таблицу смотрят.
- Сделки без диапазона входа этого таймфрейма (не хватило истории свечей) при сортировке
  по «Диапазону» всегда уходят в конец списка, независимо от направления сортировки —
  иначе клик по колонке переставлял бы местами только дыры в данных.

## Поведение сортировки

- По умолчанию — «Закрыта», по убыванию (новые сверху). Список из `/api/trades/lab`
  и так приходит в этом порядке, поэтому до первого клика по заголовку ничего не меняется.
- Первый клик по любой колонке — сортировка по убыванию: вопрос к любой из числовых
  колонок «где больше», а не «где меньше» (тот же принцип, что в `ComboTable`). Повторный
  клик по той же колонке переворачивает направление.
- Смена сортировки сбрасывает список на первый лист — так же, как сейчас работает смена
  условий слева: показывать произвольный лист (скажем, третий) только что переупорядоченного
  списка означало бы показывать не те тридцать сделок, которые человек ожидает увидеть.
- Сортировка не сбрасывается при смене условий фильтра — предпочтение «смотреть по P&L»
  переживает сужение выборки, аналогично тому, как в `AllTags` и `ComboTable` сортировка не
  сбрасывается сама по себе.

## Файлы

- `widgets/trades-table/tradeMetrics.ts` (новый) — чистые функции `rangeOf(trade, tf)` и
  `holdMinutes(openedAt, closedAt)`, переезжают сюда из `TradesTable.tsx`. `fmtHold`
  (подпись «В позиции») и сортировка колонки «В позиции» используют одну и ту же формулу
  вместо двух копий.
- `widgets/trades-table/sortTrades.ts` (новый) — `sortTrades(trades, sort, rangeTf?):
  Trade[]`, чистая функция без React и без обращения к DOM/API. Используется страницей
  Аналитики до нарезки на листы.
- `widgets/trades-table/TradesTable.tsx` (правка) — новые необязательные пропсы `sort?:
  LedgerSort` и `onSort?: (key: string) => void`, пробрасываются в `LedgerTable` без
  изменений. `sortKey` у числовых колонок выставляется только когда передан `onSort` —
  сам по себе `sortKey` красит заголовок курсором-указателем в `LedgerTable`, и без этого
  условия заголовки на Обзоре выглядели бы кликабельными, ничего не делая по клику.
- `widgets/trades-table/index.ts` (правка) — экспортирует `sortTrades` рядом с
  `TradesTable`.
- `views/analytics/Page.tsx` (правка) — состояние `useState<LedgerSort>` с дефолтом
  `{ key: 'closedAt', dir: -1 }`; полный список из `useLab` сортируется через
  `sortTrades` перед `slice()` на лист; `useEffect`, сбрасывающий лист на первый,
  реагирует и на смену условий (как сейчас), и на смену сортировки; `sort`/`onSort`
  передаются в `TradesTable`.

## Тестирование

`sortTrades` — чистая функция, юнит-тест на vitest (`sortTrades.test.ts`, рядом с уже
существующими тестами на чистые функции вроде `shared/lib/utils/range.test.ts`):

- порядок по умолчанию (`closedAt`, по убыванию) совпадает с порядком входного массива,
  когда он уже отсортирован так же;
- сортировка по `pnl` и по `entry` в обе стороны;
- сделки без `openedAt` уходят в конец при сортировке по `hold`, независимо от `dir`;
- сделки без диапазона нужного таймфрейма уходят в конец при сортировке по `range`,
  независимо от `dir`.

Компоненты (`TradesTable`, `AnalyticsPage`) без тестов — в проекте это не принято ни для
одной фичи фронтенда; проверка — `next build` и ручной проход по странице.

## Вне рамок этой работы

- Сортировка на Обзоре («Закрытые сделки») не включается — колонки получают `sortKey` в
  определении, но остаются неактивными, пока `AnalyticsPage`-подобное состояние не заведут
  и там отдельным изменением.
- Текстовый поиск по таблице не добавляется — на Аналитике его роль уже играет панель
  условий слева.
