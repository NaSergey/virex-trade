# Бектест: хедж, живое плечо и таблицы терминала по образцу продукта

## Контекст и что меняется относительно прошлой спеки

Прошлый заход (`docs/superpowers/specs/2026-09-12-backtest-position-terminal-design.md`)
прямо исключил хедж и зафиксировал плечо неизменяемым после открытия:

> Не входит: одновременно открытые лонг и шорт (хедж-режим)... Оба требуют менять
> инвариант «одна открытая сделка на сессию»... Это отдельные, более крупные проекты
> со своей спекой на движок.
>
> Плечо. Не меняется добором или правкой стопа/тейка — как на бирже, плечо позиции
> нельзя перевыставить, пока она открыта, не закрыв её.

Этот заход оба решения разворачивает. Основание — как это устроено на реальной бирже
(проект проверен только на Bybit, см. CLAUDE.md, и ориентируемся на её hedge mode):
лонг и шорт по одному символу — две независимые позиции, каждая свой вход/маржа/
ликвидация/PnL; плечо выставляется на символ целиком, общее для обеих сторон, и
меняется в любой момент — пересчитывает маржу и ликвидацию по уже открытому объёму,
не трогая ни вход, ни PnL.

Разворот попутно чинит исходную жалобу («правая панель ордера следит за позицией»):
`OrderPanel` был явно завязан на единственную открытую сделку — блокировал слайдер
плеча, подменял Long/Short на добор одной стороны и дизейблил противоположную с
подписью `hedgeUnsupported`. Хедж убирает причину этой завязки, а не прячет симптом.

## Модель

- Одна сессия — один символ, до двух одновременно открытых сделок: одна long и одна
  short, полностью независимые (свой вход, объём, стоп/тейк, закрытие, добор).
- Плечо — одно на сессию, не на сторону раздельно; коммитится сразу во все открытые
  сделки. Не влияет на qty/риск в USDT (они по-прежнему считаются от риска и дистанции
  до стопа) — только на маржу и цену ликвидации.
- Клик по направлению, которое уже открыто, — добор (как сейчас). Клик по
  противоположному — независимое новое открытие, а не замена добора.
- Риск % каждой сделки считается от текущего баланса сессии независимо от того, есть
  ли уже открытая сделка на другой стороне — так же, как на бирже: два открытых
  ордера по 1% риска дают суммарно 2% экспозиции, это ожидаемо, не баг.
- Проверка маржи при открытии/доборе (`margin ≤ session.balance`,
  `backtest.service.ts:224,295`) остаётся такой же приблизительной, какой была
  документирована в прошлой спеке (нет отдельного учёта уже занятой другой сделкой
  маржи, нет margin-ledger) — с хеджем это означает, что открыть длинную и короткую
  по 60% маржи каждая теоретически возможно, хотя вместе это больше депозита. Это
  унаследованное упрощение, не новый пробел, вводить учёт занятой маржи здесь не
  беремся — отдельная тема, та же, что и история баланса, которой в продукте нет.

## Схема данных

Без миграции. `BacktestTrade.leverage` остаётся `Float @default(1)`, но комментарий
над полем в `schema.prisma:302-306` («не меняется добором... как на бирже, плечо
нельзя перевыставить, пока открыта») удаляется — он перестаёт быть правдой. Гвард
«одна открытая сделка» не был ограничением схемы (уникального индекса нет), он целиком
в сервисном коде — менять на уровне БД нечего.

## Бэкенд

### `openTrade` — гвард по направлению, не по сессии

`backtest.service.ts:207-208`:

```ts
const open = await tx.backtestTrade.count({ where: { sessionId, exitTime: null } });
if (open > 0) throw new ConflictException(...);
```

→ добавить `direction: input.direction` в `where`. Открытие противоположной стороны
при уже открытой перестаёт кидать `BACKTEST_OPEN_TRADE`; открытие той же стороны
по-прежнему отклоняется (фронт с этой стороны и так шлёт `add`, не `open`, но серверная
защита остаётся).

### Новый метод — смена плеча сессии

`setLeverage(userId, sessionId, leverage)`, тот же паттерн блокировки, что у
`modifyTrade`/`addToTrade` (`bumpCursor` + транзакция):

- Берёт все открытые сделки сессии (`exitTime: null`).
- Для каждой проверяет `notional / leverage ≤ session.balance` (та же формула, что при
  открытии/доборе, `notional` — по текущим qty/entryPrice сделки). Если хоть одна не
  проходит — отказ целиком, без частичного применения: плечо общее на сессию, менять
  его для одной открытой стороны и отказывать для другой было бы страннее, чем просто
  отказать.
- `updateMany({ where: { sessionId, exitTime: null }, data: { leverage } })`.
- Эндпоинт `PATCH /api/backtest/sessions/:id/leverage`, DTO `{ leverage: number }`
  (`@Min(1) @Max(100)`, как у `OpenTradeDto`).
- Отдельного поля «текущее плечо сессии» в схеме не заводим — следующая сделка
  открывается с тем, что стоит на слайдере панели (фронтовый черновик, как сейчас);
  этот эндпоинт только толкает значение в уже открытые сделки.

## Симуляция (движок прокрутки)

`lib/fills.ts` (`checkMinute`, `findExit`) уже принимают одну `Position` за вызов —
сигнатуру не трогаем, просто зовём по разу на каждую открытую сделку за тот же проход
по минуткам.

`lib/advance.ts` (`advanceTo`): `position: OpenPosition | null` → `positions:
OpenPosition[]` (0–2, с `tradeId` в каждой); `exit: Exit | null` → `exits: Exit[]`
(0–2 за один вызов — по одному на сработавшую сделку). `closeOrders` фильтруются по
своему `tradeId`, как и сейчас.

`useReplay.ts:101-102,214-232`: `openRef` (одна сделка) → массив открытых
(`detail.trades.filter(x => x.exitTime == null)`, максимум 2); `advance()` строит
`positions` по каждой; `onExitRef.current` зовётся по разу на каждый элемент `exits`
(та же `closeTrade`, что и сейчас — просто может позвать её дважды за один тик).

## Фронтенд

### `ReplayChart.tsx` — уровни привязаны к сделке, не только к виду

`Level` получает `tradeId?: string`. `onDragLevel` (проп, строка 85) и `startDrag`
(строка 245) начинают нести его: `(id: string, kind: LevelKind, price: number, done:
boolean) => void`. Нужно, потому что сейчас драг репортит только `kind` — при двух
одновременно открытых сделках будет по два уровня `stop`/`take`/`entry`/`liq` разом, и
одного `kind` не хватит понять, чей уровень потащили. `id` у этих уровней меняется с
литералов (`'entry'`, `'stop'`) на составные (`` `stop-${tradeId}` `` и т.п.) — по
комментарию у `Level.id` (строка 27) он и так не обязан совпадать с `kind`, у
лимит-ордеров на закрытие уже так.

### `SessionScreen.tsx`

- `openTrade: BacktestTrade | null` → `openTrades: BacktestTrade[]`
  (`trades.filter(x => x.exitTime == null)`).
- `levels` (строки 150–170): цикл по `openTrades` вместо одного `if (openTrade)` — на
  каждую сделку свой набор `entry`/`liq`/`stop`/`take`, с `tradeId`.
- `onDragLevel` (строки 250–263) находит сделку по пришедшему `tradeId`, дальше как
  сейчас — `applyLevelsRef.current` на конкретную сделку, а не на единственную.
- `open()`: кросс-дизейбл кнопок по стороне (`sameDirectionOpen === 'short'`) больше не
  нужен здесь — переезжает в `OrderPanel` в упрощённом виде (см. ниже), а не пропадает
  бесследно.
- `limitModal`/`marketModal`/`levelsModal`: вместо `boolean` — id сделки
  (`string | null`), под которую открыта модалка, раз сделок может быть две.
- `canClose`/`closePending`: были константами сессии, становятся функциями от сделки.
- Новый хук `useSetLeverage(session.id)` (→ `PATCH .../leverage`), коммитится по
  отпусканию слайдера плеча в `OrderPanel` с дебаунсом (тем же приёмом, что у
  автосохранения курсора, `SAVE_DELAY_MS`) — не на каждый кадр: нативный `Slider`
  сейчас шлёт `onChange` раз в кадр через `requestAnimationFrame`, это годится для
  локального стейта, но не для сетевого запроса на каждое движение мыши.

### `OrderPanel.tsx`

- Пропсы `sameDirectionOpen`, `openLeverage` пропадают — панель ничего не знает о
  позиции.
- Плечо: слайдер всегда активен, `disabled={openLeverage != null}` (строка 159)
  убирается. По отпусканию — коммит через `useSetLeverage`, если открыта хоть одна
  сделка; если ни одной нет, значение остаётся локальным черновиком, как сейчас.
- Long/Short (строки 231–246): подпись и обработчик решаются по тому, открыта ли
  **своя** сторона (`openTrades.some(t => t.direction === 'long')` → «Добрать лонг» /
  `onAdd`), независимо от состояния другой стороны. Кросс-дизейбл
  (`sameDirectionOpen === 'short'` блокирует Long) убирается целиком — обе кнопки
  всегда доступны, пока хватает баланса и риск валиден.
- Блок и ключ `hedgeUnsupported` (строка 246) удаляются вместе с текстом.

### `OpenPositionsPanel.tsx` — колонки по образцу обзора, до двух строк

- `trade: BacktestTrade | null` → `trades: BacktestTrade[]`; строка таблицы — на
  каждую сделку.
- `onLimit`/`onMarket`/`onChangeLevels` принимают сделку явным параметром
  (`(trade: BacktestTrade) => void`), а не берут её из замыкания — кнопка в конкретной
  строке относится к конкретной сделке.
- Список висящих лимит-ордеров рисуется под своей строкой, отфильтрованный по
  `tradeId`, а не одним общим блоком под всей таблицей, как сейчас.
- Новые колонки, по образцу `views/overview/components/OpenPositions.tsx`:
  - **Маркировка** — `replay.price`, новый ключ `colMark`.
  - **Ликвидация** — `liquidationPrice(direction, entryPrice, leverage)` (формула уже
    есть), переиспользуем существующий ключ `liqLabel`, новый не нужен.
  - **В позиции** — новый ключ `colInPosition`, но не от `Date.now()`, как в обзоре, а
    от `replay.cursor − entryTime` (время симуляции, не настоящее).
- Осознанно не переносим из обзора: **Символ** (сессия на одну пару, и так видна на
  странице), **Диапазон входа** (в обзоре это live market-context с отдельного
  эндпоинта `useOpenPositionContext`, для бектеста такого источника данных нет),
  **Теги** (разметка остаётся только на закрытых сделках — тег на ещё не закрытой
  позиции не входит в эту задачу).
- Плечо остаётся своей колонкой — в обзоре её нет (не биржевая позиция с чужим
  плечом), это специфика бектеста.

### `SessionTrades.tsx` («История») — по образцу `TradesTable`

- Сейчас `colEntry`/`colExit` рисуют склеенную строку `"{labelFor(time)} ·
  {price}"` (строки 39, 45). Станет: ведущая приглушённая колонка **Закрыта**
  (`labelFor(exitTime)`, как `colClosed` в `TradesTable`) + отдельно **Вход**/
  **Выход** только ценой.
- Новая колонка **Размер** в USDT (`qty × entryPrice`, с тем же `qtyTitle`-тултипом в
  монете, что уже есть в `OpenPositionsPanel`) — сейчас в истории бектеста размер
  нигде не показан.
- Новая колонка **В позиции**: `entryTime → exitTime`, по формуле в духе `fmtHold` из
  `TradesTable.tsx:26-34`, но от настоящих ISO-полей сделки, без обращения к живым
  данным.
- Остаются как есть, потому что в `TradesTable` этого нет и это ценность бектеста:
  **R** (`colR`) и **Выход по** (`colReason`).
- Раскрытие строки остаётся выбором тегов (`TagPicker`), не переезжает на
  `TradeOrders`/`RangeCheckModal` из `TradesTable` — этим данным (реальные ордера
  исполнения, отдельный live-график по id сделки) в бектесте взяться неоткуда, график
  сессии и так всегда на экране.

## i18n (`ru.json`/`en.json`, неймспейс `backtest`)

- Новые ключи: `colMark` («Маркировка»), `colInPosition` («В позиции»).
- Переиспользуются как есть: `liqLabel` (уже «Ликвидация»), `addLong`/`addShort`
  (уже «Добрать лонг»/«Добрать шорт»).
- Удаляется: `hedgeUnsupported` — по смыслу больше не наступает, мёртвый ключ и текст.

## Тестирование

- `backend/src/backtest/backtest.service.spec.ts`: открытие второй сделки
  противоположного направления — успех, обе видны как открытые; открытие второй сделки
  **той же** стороны — по-прежнему `BACKTEST_OPEN_TRADE`; `setLeverage` — пересчитывает
  у всех открытых сразу, отказ при марже больше баланса хотя бы у одной (ни одна не
  обновляется).
- `frontend/src/views/backtest/lib/fills.test.ts`, `advance.test.ts`: кейс с двумя
  открытыми позициями в одном окне проверки — обе срабатывают в одном проходе по
  минуткам, только одна, ни одна.
- Ручная проверка на дев-сервере: открыть лонг, поверх открыть шорт — две строки в
  таблице, два набора уровней на графике; независимые закрытие/добор/лимитки на каждой
  стороне; подвинуть плечо при обеих открытых — обе строки пересчитывают ликвидацию.
- Меняются схема (комментарий), бэкенд (новый метод, эндпоинт, DTO) и несколько слоёв
  фронта — это «крупное изменение» по глобальным правилам: перед коммитом `next build`
  и полный прогон бэкенд-тестов, не только `tsc`.

## Порядок реализации

1. Бэкенд: гвард `openTrade` по направлению + тесты.
2. Бэкенд: `setLeverage` (метод, DTO, эндпоинт) + тесты.
3. Движок: `fills.ts` на вызов по каждой сделке, `advance.ts`/`useReplay.ts` на массив
   позиций/исходов + тесты.
4. `ReplayChart.tsx`: `tradeId` в `Level` и в сигнатуре `onDragLevel`.
5. `SessionScreen.tsx`: `openTrades`, циклы по уровням, модалки по id сделки,
   `useSetLeverage` с дебаунсом.
6. `OrderPanel.tsx`: снять пропсы о позиции, кросс-дизейбл, плечо всегда активно.
7. `OpenPositionsPanel.tsx`: до двух строк, новые колонки, обработчики по сделке.
8. `SessionTrades.tsx`: колонки по образцу `TradesTable`.
9. i18n: новые/удалённые ключи в `ru.json`/`en.json`.
