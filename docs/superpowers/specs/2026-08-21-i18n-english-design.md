# Локализация Virex на английский

Дата: 2026-08-21

## Контекст

Фронтенд — не многостраничный сайт с роутами, а SPA-оболочка (`frontend/src/app/page.tsx`):
один `AppShell`, вкладки переключаются React-стейтом (`activeTab`), а не URL. Кроме `/` и
`/login` реальных Next-роутов нет. Это определяет решения ниже: URL-based locale routing
(стандартная схема `next-intl` через middleware) продукту ничего не даёт — SEO не нужно, за
логином всё равно всё спрятано.

Объём на момент написания: ~59 файлов фронтенда с кириллицей, ~38 сообщений об ошибках в
NestJS-исключениях на бэкенде. Все решения ниже — по итогам обсуждения с пользователем.

## Решения

- **Библиотека:** `next-intl`, без встроенного routing/middleware — только
  `NextIntlClientProvider`, локаль в React-контексте.
- **Роутинг:** без префикса в URL. Локаль — состояние приложения, не адреса.
- **Бэкенд-ошибки:** коды + перевод на фронте. NestJS не подключает i18n-библиотеку;
  исключения дополнительно несут стабильный `code`, текст остаётся на бэкенде как fallback.
- **Заход:** поэтапно. Сегодняшний план и спек покрывают только Phase 0 (инфраструктура +
  первый экран). Остальные страницы — механическое повторение того же паттерна без нового
  брейнсторминга под каждую.
- **Telegram-уведомления бэкенда — вне периметра.** Это не «сайт»; не трогаем, пока не попросят
  отдельно.

## Архитектура

### Локаль и провайдер

`frontend/src/shared/i18n/`:

- `LocaleProvider` — React-контекст с `locale: 'ru' | 'en'`. Инициализация из
  `localStorage.getItem('virex-locale')`, дефолт `'ru'`. **Без auto-detect по
  Accept-Language** — при первом заходе для всех остаётся русский, язык меняется только
  явным действием пользователя. При смене locale обновляет `document.documentElement.lang`
  (сам layout.tsx остаётся server-rendered со статичным `lang="ru"` — это дефолт для
  первого пейнта до гидратации, не баг).
  Оборачивает детей в `<NextIntlClientProvider locale={locale} messages={messages[locale]}>`.
- `messages/ru.json`, `messages/en.json` — статические импорты (оба сразу; SPA без
  code-splitting по роутам, файлы небольшие — динамическая подгрузка не оправдана).
  Namespace верхнего уровня = FSD-слайс: `common`, `nav`, `auth`, `overview`, `tags`, `lab`,
  `analytics`, `settings`, `errors`.
- `LocaleSwitch` — компонент-переключатель на базе существующего `shared/ui/Seg` (тот же
  визуальный паттерн, что BTC/ETH/SOL на странице «Рынок»): две кнопки `RU`/`EN`. Ставится в
  `TopNav.tsx`, в `.top-r`, рядом с кнопкой «Профиль».

### Локаль-зависимое форматирование

Сейчас `'ru-RU'` захардкожен в 13 местах: `shared/lib/utils/format.ts`, `shared/lib/utils/period.ts`,
и по месту в `TradesTable.tsx`, `TradeOrders.tsx`, `RangeCheckChart.tsx`, `EquityChart.tsx`,
`PeriodRail.tsx`, `SentimentChart.tsx`, `TradeTagsModal.tsx`.

Функции в `shared/lib/utils/format.ts` начинают принимать `locale` параметром вместо жёсткого
`'ru-RU'`. Миграция вызывающих мест — **не отдельным проходом**, а по одному файлу за фазу, в
которую этот файл попадает (см. «Фазы» ниже). До миграции конкретного файла даты в нём
показываются в русском формате независимо от выбранного языка — известное и осознанно
принятое ограничение промежуточных фаз, не баг.

### Бэкенд-ошибки: коды вместо строк

Было:

```ts
throw new UnauthorizedException('Неверный email или пароль');
```

Станет:

```ts
throw new UnauthorizedException({ message: 'Неверный email или пароль', code: 'INVALID_CREDENTIALS' });
```

`message` остаётся — fallback для ещё не мигрированных мест и для логов. `code` — новое поле,
аддитивное изменение, ничего не ломает у потребителей, которые его не читают.

На фронте `shared/api/http.ts` получает `resolveApiError(body, t)`:

1. если `body.code` есть и `errors.<code>` есть в каталоге сообщений текущей локали — вернуть
   перевод;
2. иначе — вернуть `body.message` как есть (текущее поведение, по-русски).

`apiJson()` — единственное место, где сейчас централизованно парсится тело ошибки; он
переходит на `resolveApiError` в Phase 0. Часть фич дергает `apiFetch` напрямую и парсит
ошибку по месту (копипаста той же проверки) — такие места переводятся на `resolveApiError`
в фазе, которая трогает соответствующую фичу, не одним общим проходом.

Миграция `throw` на `{ message, code }` идёт по бэкенд-модулям, связанным с фазой на фронте:
Phase 0 — только `auth.service.ts` (это первое, с чем сталкивается новый пользователь). Коды
для остальных ~34 сообщений — по мере фаз 1–5, зачистка оставшегося — в фазе 6.

## Фазы — все выполнены (2026-08-22)

Каждая фаза добавляла свой namespace в `messages/*.json`, заменяла захардкоженные строки в
файлах своей страницы на `useTranslations(...)` и переводила относящиеся к ней бэкенд-исключения
на `{ message, code }` — без повторного дизайна, паттерн подтвердился с первой фазы.

0. **Инфраструктура**: `next-intl` в зависимости, `LocaleProvider`, `messages/{ru,en}.json`
   (namespaces `common`, `nav`, `auth`), locale-параметр в `shared/lib/utils/format.ts`,
   `LocaleSwitch` в `TopNav.tsx`, `resolveApiError` в `shared/api/http.ts`, миграция
   `auth.service.ts` на коды ошибок. Строки переводятся в `login/page.tsx`, `TopNav.tsx`,
   `AuthGuard` (из `features/auth`).
1. **Обзор** (`views/overview`) + попутно общие зависимости: `PeriodStrip`/`PeriodRail`,
   `Pagination`, `ConfirmDialog`/`dialog.tsx` (общие `shared/ui`), `weekdayLabels`/
   `formatPeriodRange` в `shared/lib/utils/period.ts`, `durationUnitLabels` в `format.ts`.
2. **Теги** (`views/tags`) + `useTagTypeLabels` (`entities/tag`, был статическим объектом —
   стал хуком, используется и в `TagPicker` на «Обзоре»).
3. **Выборка** (`views/lab`) + `widgets/trades-table` (таблица закрытых/подходящих сделок,
   общая с «Обзором») и `widgets/range-check-modal` (график диапазона входа).
4. **Рынок** (`views/analytics`) + попутно найденный и закрытый пробел в
   `widgets/equity-chart` (кривая P&L, общая с «Обзором» и «Выборкой») — подсказка при
   наведении не была переведена; число сделок в просадке считается через ICU-plural
   next-intl (`{n, plural, one {…} few {…} many {…}}`), а не вручную.
5. **Настройки** (`views/settings`) + подсказки о правах ключа API (`permissionsHint`) —
   раньше приходили строкой с бэкенда, теперь бэкенд отдаёт их как fallback, а фронт по
   `exchange.id` подставляет перевод (`usePermissionsHints`, тот же приём, что коды ошибок,
   но для каталога бирж, где кода пока нет) — плюс заголовок вкладки и meta-description
   (`layout.tsx` → `generateMetadata`, раньше были статикой на русском).
6. **Зачистка**: грепом по кириллице (`grep -rlP "[а-яА-ЯёЁ]"`) по всему `frontend/src`
   подтверждено — в пользовательских строках ничего не осталось (комментарии с
   обоснованиями остаются русскими, это документация для разработчика). Заодно нашлись и
   закрылись места, не попавшие ни в одну из фаз 1–5, потому что лежат в `shared/lib`, а не
   в `views/*`: `formatRangePos` (`shared/lib/utils/range.ts`, подпись «82% · верх» на
   «Обзоре», «Выборке» и в раскрытой записи журнала) и `errorMessage`
   (`shared/lib/utils/error.ts`) — у неё убран русский дефолт `fallback`, теперь он
   обязателен, чтобы не тёк через `ErrorNote` тихо. Бэкенд-исключения мигрированы на коды
   везде, кроме `telegram.service.ts` (вне периметра, см. ниже) и `analytics.service.ts`
   (текст уже на английском, переводить нечего).

### Решено: `resolveApiError` умеет `params`

Часть бэкенд-сообщений несёт не только текст, но и конкретику — какая биржа, что именно
запрещено (`` `${meta.label} требует passphrase…` ``). Код без параметров стирал бы эту
конкретику даже для русской версии: `resolveApiError` подставляет `errorMessages[code]`
целиком, теряя исходный `message` с бэкенда. Поэтому исключение получило необязательное поле
`params: Record<string, string>`, а `resolveApiError` — подстановку `{key}` в переведённый
шаблон (`frontend/src/shared/api/http.ts`). Проверено `http.test.ts`.

## Решено: источник локали — кука, не localStorage

Раньше `LocaleProvider` читал `localStorage` в ленивом инициализаторе `useState` — этот код
выполняется и на гидратации, то есть на первом клиентском рендере, который React сверяет с
серверным HTML. Сервер по умолчанию всегда рендерил `'ru'` (доступа к `localStorage` у него
нет), поэтому у пользователя с ранее сохранённым `'en'` сервер присылал русский текст, а
клиент сразу после гидратации перерисовывал его в английский — заметная вспышка RU→EN и
ошибка hydration mismatch в консоли; итоговый результат при этом был корректным.

Решение принято раньше срока (был замечен на `/`, а не только на `/login`): локаль перенесена
на куку `virex-locale` (`frontend/src/shared/i18n/locale-storage.ts`), которую `layout.tsx`
читает на сервере через `next/headers` и передаёт как `initialLocale` в `LocaleProvider` —
сервер и клиент читают один и тот же источник, гидратация больше не расходится. Расплата —
осознанная: `layout.tsx` стал `async` и читает `cookies()`, из-за чего все страницы (`/`,
`/login`, `/_not-found`) стали динамическими (`ƒ`) вместо статических. Одноразовая миграция
старого `localStorage`-значения — в `LocaleProvider` (`useEffect` на маунте): если куки ещё
нет, но есть старое значение, оно подхватывается и переносится в куку.

## Что не входит

- Telegram-бот и его сообщения.
- URL-роутинг по локали (нет причины — см. «Контекст»).
- Auto-detect языка браузера при первом визите.
- i18n-библиотека на бэкенде (nestjs-i18n и т.п.) — только коды ошибок.
- Профессиональная вычитка английского текста носителем — переводы делает Claude, без
  отдельного ревью терминологии. Если после Phase 0 формулировки не понравятся — правится
  по ходу, это не блокер для старта.
