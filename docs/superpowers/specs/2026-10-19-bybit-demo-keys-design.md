# Ключи демо-счёта Bybit — «Bybit Demo»

Дата: 2026-10-19. Запрос владельца: демо-аккаунт Bybit не подключается к сайту.

## Причина

У Demo Trading Bybit свои адреса: REST — `https://api-demo.bybit.com`, приватный
поток — `wss://stream-demo.bybit.com/v5/private`
(https://bybit-exchange.github.io/docs/v5/demo). Ключ, созданный в демо-режиме, существует
только там. Продукт ходил только на `api.bybit.com` — демо-ключ получал «API key is invalid».

## Решение (выбор владельца)

**Отдельная биржа в каталоге — `bybit-demo`, «Bybit Demo»**, а не флажок у Bybit. Можно
держать оба ключа сразу и переключаться между ними, как между биржами; сделки демо пишутся с
`Trade.exchange = 'bybit-demo'` и от настоящих отличимы.

## Устройство

- **Признак — `demo: true` в учётных данных** (`ExchangeCredentials`, `BybitCredentials`).
  Каждый подписанный запрос к Bybit и так получает их аргументом, поэтому адрес выбирается
  там же: `bybitBase(demo)` в `bybit-gate.ts` (`BYBIT_API` или `BYBIT_DEMO_API`), сокет —
  `BYBIT_PRIVATE_WS` или `BYBIT_PRIVATE_WS_DEMO`. Хранить признак в базе не нужно: он
  выводится из `exchange` строки подключения.
- Откуда берётся признак:
  - `CredentialsService.get(userId, 'bybit-demo')` кладёт его в расшифрованные данные —
    так его получают терминал, поток счёта и синк;
  - `BybitDemoAdapter` (наследник `BybitAdapter`) ставит его сам на всё, что ему передали, —
    так проходит проверка ключа при подключении, где данные ещё сырые из формы.
- **Публичные данные — с основного адреса** (свечи, тикеры, инструменты, маркировка): по
  документации Bybit они у демо те же. Меняются только запросы с ключом.
- **Шлюз один на оба адреса**: бюджет и пауза после 403 — общие. Считает ли Bybit лимит IP
  по двум хостам вместе, документация не говорит; общий бюджет — строгая сторона.
- **Права ключа** — тем же `/v5/user/query-api`: на `api-demo.bybit.com` маршрут есть
  (проверено запросом с фиктивным ключом: 10003 «API key is invalid», а не 404). Правило
  терминала прежнее — доступ только при `canPlaceOrders`.
- **Терминал** открывается при активной `bybit` или `bybit-demo` (`isBybit`) и торгует ключом
  активной из двух. Снимок счёта в кэше `api` — по пользователю и ключу: после переключения
  настоящий ↔ демо не показывается счёт другого. Подпись над графиком — «Bybit · демо-счёт».
- Все приватные методы, которыми пользуются журнал и терминал, у демо есть (список на
  странице документации): `order/*`, `position/list|set-leverage|trading-stop|closed-pnl`,
  `execution/list`, `account/wallet-balance`, приватный поток `position`/`order`/`wallet`.

## Не входит

- Пополнение демо-счёта из продукта (`/v5/account/demo-apply-money`).
- Скрытие демо-сделок из журнала и профиля: демо — такая же биржа, как остальные.

## Проверка

Юнит-тесты: адрес по признаку, демо-адаптер ставит признак, учётные данные `bybit-demo`
несут его, сокет выбирает адрес, инвариант шлюза знает оба хоста. Живым демо-ключом —
владелец: подключить «Bybit Demo», открыть терминал, поставить и снять лимит.
