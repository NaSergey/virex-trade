# Профиль: чужие страницы, аватар, красочный экран и новые окна наград

Запрос владельца 2026-10-01, поверх `2026-10-01-profile-dashboard-design.md`:

1. Страница профиля — ровно экран, без прокрутки страницы.
2. Игроки заходят на профили друг друга и видят статистику — **всё целиком**,
   как сам владелец профиля (решение владельца).
3. Свою картинку можно поставить на профиль.
4. Профиль красочный, как окна наград; окна наград переделать — «мало движения,
   тускло, мало цвета, плоские скучные карточки».

## Адреса

- `/profile` — свой профиль (как сейчас).
- `/profile/<userId>` — чужой. Свой id в этом адресе показывает тот же свой
  профиль. Неизвестный id — пустое состояние «игрок не найден».
- Ссылки на чужой профиль — имя игрока в рейтинге (`widgets/tournament-rating`)
  и в ленте сделок игроков турниров. Своя строка тоже ссылка.

## Что видно на чужом профиле

Всё, что на своём: шапка (имя, аватар, уровень сезона, XP), плитки (место, очки,
турниры, победы, монеты), достижения, активность, где играет, опыт, баланс
монет, лента журнала монет, игры, рейтинг. Почта не показывается нигде — она не
статистика. Имя без заданного — «—», то же правило, что у рейтинга.

Кнопок наград и смены картинки на чужом профиле нет: забрать чужую награду
нельзя.

## Сервер

- `GET /api/profile` — свой, `GET /api/profile/:userId` — любой. Ответ один и тот
  же, к прежнему добавляется:
  ```ts
  user: { id: string; name: string | null; avatar: string | null };
  season: { key: string; endsAt: string; xp: number; level: number; xpIntoLevel: number; xpToNext: number };
  balance: number;                // User.coinBalance
  rating: RatingRow | null;       // строка этого игрока в рейтинге игры
  ```
  `season` — из `levelFromXp` и `seasonKey` Battle Pass (одно правило уровней),
  `rating` — строка игрока из того же ранжирования, что у `rating.ts`
  (`rankAll`, одно правило очков; `ratingRows` строится поверх него). Чужой
  профиль больше не читает Battle Pass, баланс и рейтинг своими ключами: это
  ключи смотрящего. Свой профиль по-прежнему берёт Battle Pass для кнопок наград.
  Неизвестный id — 404 `PROFILE_NOT_FOUND`. `:userId` — UUID, иначе 404.
- **Аватар.** Байты — в отдельной таблице `UserAvatar (userId PK, data Bytes,
  mime, updatedAt)`, а не колонкой `User`: Prisma читает все скаляры по
  умолчанию, и картинка ехала бы с каждым `findUnique` пользователя. На `User` —
  `avatarAt DateTime?`: есть ли картинка и её версия.
  - `PUT /api/profile/avatar` (multipart, поле `file`) — до 512 КБ; тип — по
    первым байтам (PNG, JPEG, WebP), не по заголовку клиента. SVG и всё прочее —
    400 `AVATAR_TYPE`. Строка и `avatarAt` пишутся одной транзакцией.
  - `DELETE /api/profile/avatar`.
  - `GET /api/profile/:userId/avatar` — **без авторизации**: `<img>` не несёт
    Bearer-токен, а картинка видна всем игрокам и так. Отдаётся с тем типом,
    что определён по байтам, `X-Content-Type-Options: nosniff`,
    `Content-Security-Policy: default-src 'none'`, кэш год — адрес версионный.
  - Адрес картинки строит сервер: `/api/profile/<id>/avatar?v=<avatarAt мс>`;
    он едет в `PublicUser.avatar` (`/auth/*`) и в `user.avatar` профиля.
- Клиент перед загрузкой режет картинку в квадрат по центру и сжимает до
  256×256 WebP (canvas): сервер не перекодирует картинки и новых зависимостей не
  получает.

## Фронт: экран

- **Профиль — тёмная игровая страница** в обеих темах, как витрина игр
  (`isGamesDarkRoute` включает `/profile*`): он про игры и сезон, и краски игр
  живут на чёрном поле. Радиусы и свет — исключением в `@layer base` (`.pf`).
- **Цвет — не на игру.** Игр будет 20+, и двадцать разных цветов не различить.
  Цвет несут смыслы, а не игры: опыт — фиолетовый (сезон), монеты — янтарь,
  активность — зелёный, достижения — у каждого свой тон из короткой шкалы.
  Паутинка показывает **шесть самых частых игр**, а не все: ось на двадцать
  игр нечитаема. Таблица игр — все, отсортированные по дням за 90, с
  прокруткой внутри панели.
- **Шапка — карточка игрока**: аватар в кольце уровня (кольцо — прогресс XP до
  следующего уровня, номер уровня — значком на кольце), имя, «в игре с …»,
  полоса XP, плитки, справа — две большие цветные кнопки наград (сундук
  ежедневной, медаль сезона) с точкой/суммой. На своём профиле по аватару —
  кнопка «Сменить картинку» (выбор файла, удалить).
- **Ровно экран** на ширине ≥1100 и высоте ≥720: страница —
  `height: calc(100dvh - var(--top-h))`, сетка панелей делит остаток, у панелей
  `min-height: 0`; длинное (лента, рейтинг, игры) прокручивается внутри своей
  панели. Графики тянутся по высоте панели (`ResizeObserver` на высоту тоже).
  Ниже этих размеров — обычная прокрутка страницы.
- Раскладка: шапка; слева два ряда по три панели — [достижения | активность |
  где играет], [опыт | монеты | лента]; справа колонка [игры, рейтинг].

## Окна наград

Общее: окна ярче — насыщенный градиент поля в цвет окна, лучи света за главным
предметом, предметы вместо плоских прямоугольников, движение в покое и на
выдаче. Всё движение — `transform`/`opacity`, кадр 0 % = кадр 100 %, под
`prefers-reduced-motion` состояние меняется сразу.

- **Ежедневная** (янтарь → оранжевый). Семь дней — предметы, растущие по неделе:
  монета → стопка → горка монет → **сундук** на седьмой. Сегодняшний — крупнее,
  на подставке, за ним вращаются лучи, сам покачивается. Выдача: подпрыгивает,
  разлетаются монеты, сумма «+N» взлетает, у сундука открывается крышка.
  Пройденные — штамп-галочка с ударом.
- **Сезон** (фиолетовый → маджента). Медаль уровня — шестиугольник с
  градиентом и светом, полоса XP с ярким концом. Лента уровней остаётся
  горизонтальной (владелец её не отметил), но карточки — предметы по размеру
  награды (стопка/горка), каждый десятый уровень — сундук. Под лентой — путь с
  узлами-кружками, пройденные светятся. Готовые карточки покачиваются с лучами;
  выдача — карточки по очереди подпрыгивают с разлётом монет, сумма в кнопке
  отсчитывается вниз до нуля.

Предметы (монета, стопка, горка, сундук) — один SVG-компонент
`shared/ui/RewardItem` на оба окна.
