# Бектест: частичное закрытие позиции лимитками и по рынку

## Контекст и порядок относительно спеки про плечо/добор

`docs/superpowers/specs/2026-09-12-backtest-position-terminal-design.md` — уже
одобренная, но ещё не реализованная спека (плечо, добор позиции той же стороны,
безусловный `OrderPanel`, полоса `PositionBar` над терминалом с кнопкой «Закрыть по
рынку», модалка «Изменить TP/SL», уровень ликвидации на графике). Она прямо исключает
частичное закрытие лимитками как «отдельный, более крупный проект со своей спекой на
движок» — это и есть настоящий документ.

**Порядок реализации: сначала спека про плечо/добор, потом эта.** Причина не только в
том, что она старше по очереди, а в том, что обе спеки претендуют на одно и то же место
экрана — показ открытой позиции и её закрытие. Не имеет смысла один раз собирать
`PositionBar` над терминалом (плечевая спека), а следом переносить его же ниже графика
и переделывать под вкладки (эта). Поэтому:

- Всё из плечевой спеки реализуется как есть — `OrderPanel` без веток по `openTrade`,
  плечо, добор, модалка «Изменить TP/SL», уровень `liq` на графике.
- **Кроме размещения и кнопки закрытия `PositionBar`** — этот пункт плечевой спеки
  отменяется этим документом. Полоса над терминалом не строится; открытая позиция и её
  закрытие переезжают под график, туда, где сейчас `SessionTrades`, — по дизайну ниже.
  Модалка «Изменить TP/SL» из плечевой спеки остаётся (правка стопа/тейка — это не
  закрытие), а вот «Закрыть по рынку» из неё вычёркивается: рынок и лимит закрытия
  теперь два равноправных способа в новой таблице, а не один в старой панели.

## Что остаётся без изменений

- Инвариант «одна открытая позиция на сессию» (`BacktestTrade.exitTime == null`) —
  частичное закрытие не открывает вторую позицию, только уменьшает объём первой.
- `summarize`, `maxDrawdownPct`, `stats` (`backtest.service.ts`) — как считали список
  `{pnl, r}` по `BacktestTrade`, так и продолжают: число сделки не раздувается частичными
  выходами, ровно как `collapseToPositions` не раздувает счётчик в обычном журнале.
- Приоритет стопа над тейком при срабатывании внутри одной минутки (`checkMinute`) —
  не меняется, лимит-ордера встраиваются в эту же цепочку ниже него.

## Модель данных

```prisma
model BacktestTrade {
  // ...существующие поля без изменений...
  closedQty     Float    @default(0) // сколько уже закрыто частями; qty - closedQty = остаток
  exits         BacktestTradeExit[]
  closeOrders   BacktestCloseOrder[]
}

/// Одно частичное или финальное закрытие открытой сделки. exitTime/exitPrice/pnl/r
/// на самой BacktestTrade заполняются только когда closedQty достигает qty — это
/// агрегат по всем строкам ниже, а не отдельное событие.
model BacktestTradeExit {
  id      String        @id @default(uuid())
  tradeId String
  trade   BacktestTrade @relation(fields: [tradeId], references: [id], onDelete: Cascade)
  qty     Float
  price   Float
  time    DateTime
  reason  String // 'stop' | 'take' | 'manual' | 'finish' | 'limit'
  fee     Float
  pnl     Float

  @@index([tradeId])
  @@map("backtest_trade_exits")
}

/// Висящий лимитный ордер на (частичное) закрытие. Живёт до срабатывания цены в
/// реплее или ручной отмены; на одну сделку может висеть несколько одновременно.
model BacktestCloseOrder {
  id        String        @id @default(uuid())
  tradeId   String
  trade     BacktestTrade @relation(fields: [tradeId], references: [id], onDelete: Cascade)
  price     Float
  qty       Float
  createdAt DateTime      @default(now())

  @@index([tradeId])
  @@map("backtest_close_orders")
}
```

`ExitReason` (фронт и бэк) получает значение `'limit'` в объединение
`'stop' | 'take' | 'manual' | 'finish' | 'limit'`. Отдельного `'market'` не заводим —
немедленное закрытие по текущей цене (полное или частичное) остаётся `'manual'`, как
сегодня; отличает его от лимита не причина, а то, что оно происходит сразу, а не после
срабатывания цены.

Теги (`BacktestTradeTag`) остаются на `BacktestTrade` целиком — сетап описывает решение
войти, а не то, какой частью сделку закрыли; разбивку по `BacktestTradeExit` в UI не
показываем (см. «Вне рамок» ниже).

Миграция — `npx prisma migrate dev` в `backend`, после остановки `nest watch`
(память `prisma_generate_eperm_windows`: генератор падает `EPERM`, если процесс держит
движок).

## Бэкенд

### `POST /api/backtest/trades/:tradeId/close`

`CloseTradeDto` получает необязательное `qty` (`@IsOptional() @IsPositive()`). Логика:

1. `remaining = trade.qty - trade.closedQty`; `qty` по умолчанию = `remaining`
   (все существующие вызовы — стоп, тейк, `finish`, ручное закрытие из будущей модалки
   «Маркет» на 100% — ничего не передают и получают ровно сегодняшнее поведение).
2. `qty > remaining` — `BadRequestException` (`BACKTEST_QTY_EXCEEDS_REMAINING`).
3. `tradeResult({ ..., qty })` — та же функция, что и сейчас, просто с частью объёма
   вместо всего (она уже параметризована по `qty`, менять `backtest-math.ts` не нужно).
4. В транзакции (тот же `bumpCursor` + CAS, что и сегодня, только условие на
   `updateMany` теперь `{ id: tradeId, closedQty: <текущее значение> }`, а не
   `exitTime: null`, — второй параллельный запрос с тем же `closedQty` не пройдёт):
   - создаётся `BacktestTradeExit`;
   - `trade.closedQty` инкрементируется на `qty`;
   - `session.balance` инкрементируется на `pnl` этой части — как сейчас;
   - если после инкремента `closedQty === trade.qty` — вдобавок агрегируются
     `exitTime` (время этой части), `exitPrice` (цена этой части), `exitReason`
     (причина этой части), `fee`/`pnl` (сумма по всем `BacktestTradeExit` сделки, включая
     только что созданную), `r = pnl / riskUsdt`.
5. Повтор того же запроса (потерянный ответ, `useCloseTrade` ретраит до 3 раз) —
   тот же принцип, что и сегодня, только сравнение идёт не с полями самой `trade`
   (у частичного закрытия `exitTime` не проставляется), а с последним
   `BacktestTradeExit` этой сделки: если `updateMany` по `closedQty` не задел ни одной
   строки (кто-то уже применил это закрытие или гонка с другим закрытием той же
   сделки), сервер перечитывает сделку и её `exits`. Совпадает последний `exit` по
   `(qty, price, time, reason)` — это тот же самый запрос, вернувшийся повтором:
   отдаём его и текущий баланс, не начисляя PnL второй раз. Не совпадает — это
   настоящий конфликт (остаток изменился под запросом), кидаем `ConflictException`;
   `onSettled` в хуках уже перечитывает сессию, так что экран покажет, что осталось
   на самом деле.

### Лимитные ордера

- `POST /api/backtest/trades/:tradeId/close-orders` — `{ price, qty }`. Сервер проверяет
  только то, что не зависит от текущей цены: сделка открыта, `price > 0`,
  `qty ≤ remaining`. По какую сторону от рынка стоит цена (условие срабатывания в
  реплее) не проверяет — той же причине, что и `modifyTrade` не проверяет сторону
  стопа/тейка при правке: текущую цену знает браузер, а не сервер. Браузер валидирует
  сторону перед отправкой (`checkLevels`-подобная проверка в модалке), сервер —
  источник истины только для арифметики и владения.
- `DELETE /api/backtest/close-orders/:orderId` — отменить, только владельцу сделки.
- `GET /api/backtest/sessions/:id` — `SessionDetail.closeOrders: BacktestCloseOrder[]`
  (все висящие ордера открытой сделки; сессия хранит максимум одну открытую сделку, так
  что фильтр по `tradeId` не нужен — просто все ордера, чья сделка ещё не закрыта).
- Срабатывание лимит-ордера **тоже** идёт через `POST .../close` — браузер, обнаружив в
  реплее касание/гэп цены лимит-ордера (см. ниже), шлёт `{ exitTime, exitPrice, reason:
  'limit', qty: order.qty, closeOrderId: order.id }`. `closeTrade` дополнительно удаляет
  строку `BacktestCloseOrder` в той же транзакции — если её уже нет (гонка с ручной
  отменой), не ошибка, а no-op по этой части запроса.

## Логика исполнения в реплее (`lib/fills.ts`, `lib/advance.ts`)

`checkMinute` получает третий параметр — список висящих лимит-ордеров
(`{ id, price, qty }[]`) — и расширяет существующую пятишаговую проверку до:

1. Гэп за стоп (открытие свечи хуже стопа) → `stop`, весь остаток, цена = открытие.
2. Гэп за тейк → `take`, весь остаток, цена = тейк.
3. Гэп за лимит-ордером (открытие свечи прошло цену ордера) → если таких несколько,
   срабатывает ближайший по цене к открытию свечи; цена исполнения = цена ордера (не
   открытия — лимит не исполняется лучше заявленного, тот же принцип, что у тейка),
   `qty` = объём ордера.
4. Касание стопа → `stop`, весь остаток, цена = стоп.
5. Касание тейка → `take`, весь остаток, цена = тейк.
6. Касание лимит-ордера (диапазон свечи задел цену) → ближайший к открытию среди
   задетых, цена = цена ордера, `qty` = объём ордера.

За одну минутку срабатывает не больше одного события — как и сегодня; после любого
исполнения (частичного или полного) автопрокрутка останавливается
(`replay.setSpeed(null)`), пользователь видит результат явно. Если стоп или тейк закрыли
остаток целиком, оставшиеся лимит-ордера теряют смысл (сделка уже закрыта), но сами по
себе не пропадают: `BacktestTrade` не удаляется при закрытии, а `onDelete: Cascade`
срабатывает только на удаление родителя. Поэтому сервер при финальном закрытии
(`closedQty === qty`, тот же шаг транзакции, где проставляются агрегаты) явно удаляет
все оставшиеся `BacktestCloseOrder` этой сделки — висящий ордер на уже закрытую позицию
не должен всплывать, если пользователь откроет следующую сделку сессии.

`Exit` (`lib/fills.ts`) получает необязательные `qty?: number` и `closeOrderId?: string`
— заполнены только у `reason: 'limit'`; у стопа/тейка `qty` остаётся неявным (весь
остаток — так решает сам `closeTrade` без параметра).

## Фронтенд

### Вкладки под графиком

Место, где сегодня `SessionTrades` рисуется на весь экран во время активной сессии,
получает `Seg` с двумя значениями: **«Открытые позиции»** и **«История сделок»**.
Второе — сегодняшний `SessionTrades` без изменений. Первое — новый компонент.

### `OpenPositionsPanel.tsx` (новый)

`LedgerTable` в духе `overview/components/OpenPositions.tsx`, одна строка на открытую
сделку (их не больше одной): направление, вход, остаток (`qty - closedQty`) монетой и
номиналом, PnL по остатку (`unrealizedPnl` от текущей цены, как в `OrderPanel` сейчас),
кнопки **«Лимит»** и **«Маркет»**. Под строкой сделки — раскрывающийся список висящих
`closeOrders`, если есть: цена / объём / кнопка отмены каждого.

Когда открытой сделки нет — вкладка показывает `EmptyState`, а не пустую таблицу (тот же
приём, что `overview/components/OpenPositions.tsx` — целиком скрывается, только здесь
компонент вкладки должен что-то показать, раз вкладка выбрана явно).

### `LimitCloseModal.tsx` / `MarketCloseModal.tsx` (новые)

По образцу `shared/ui/dialog.tsx` (`Dialog`/`DialogHeader`/`DialogBody`/`DialogActions`),
без Post-Only/Max Slippage со скринов Bybit — это чисто биржевые механизмы без аналога в
бэктесте.

- **Лимит**: `Field` с ценой закрытия (`Input`, экранная цена — та же конвертация
  `toScreen`/`fromScreen`, что везде в бэктесте) + `Field` с объёмом (`Input` + `Slider`
  0–100% от остатка, как на скрине). Подпись под полями — предпросмотр: «при достижении
  цены закроется N монет, результат ±X USDT» (`levelImpact`, уже есть в `lib/money.ts`).
  Confirm зовёт `useCreateCloseOrder`.
- **Маркет**: только объём (`Input` + `Slider` 0–100%), предпросмотр по текущей цене
  (`unrealizedPnl` на введённый `qty`, а не на весь остаток). Confirm зовёт
  `useCloseTrade` с явным `qty`, `exitPrice: replay.price`, `reason: 'manual'`.

### Уровни на графике (`ReplayChart.tsx`)

Висящие лимит-ордера рисуются как ещё один вид `Level` (`kind: 'limitClose'`), рядом со
стопом/тейком — пунктир своим цветом, не перетаскиваемый (двигать — значит отменить
старый и поставить новый через модалку, отдельного UX для драга не делаем, это лишний
код ради редкого действия).

### `SessionScreen.tsx`

- `openM`/`modifyM`/`closeM` — как есть; добавляются `useCreateCloseOrder`,
  `useCancelCloseOrder` рядом.
- `onDragLevel`/`levels` (`useMemo`) — список уровней пополняется висящими
  `closeOrders` из `detail`.
- Проверка срабатывания в `useReplay`/`advanceTo` получает `closeOrders` открытой сделки
  третьим полем позиции для проверки.

### API-слой

- `BacktestTrade`: `+closedQty: number`.
- `SessionDetail`: `+closeOrders: BacktestCloseOrder[]`.
- `useCloseTrade` — тело мутации получает необязательный `qty`.
- `useCreateCloseOrder(sessionId)` / `useCancelCloseOrder(sessionId)` — новые хуки,
  `onSettled` тот же `refresh`.

## Вне рамок (YAGNI)

- Разбивка позиции на отдельные частичные строки в истории сделок — вкладка
  «История» показывает готовый агрегат `BacktestTrade` одной строкой, `reason` —
  последнего исполнившегося события. Разбор «из чего сложился результат» по
  `BacktestTradeExit` можно добавить позже отдельной модалкой (аналог
  `positionOrders` в обычном журнале), если понадобится — сейчас не требуется.
- Перетаскивание лимит-ордера прямо по графику мышью.
- Хедж (одновременный лонг и шорт) — по-прежнему вне рамок, как и в плечевой спеке.

  `closedQty` и не трогает `exitTime`; второе закрытие остатка проставляет агрегаты
  (сумма `pnl`/`fee`, `r` по сумме); закрытие больше остатка отклоняется; создание/отмена

- `frontend/.../lib/money.test.ts`: предпросмотр модалок (если считается новой чистой
