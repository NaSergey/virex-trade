### Создан компонент `RulesSection.tsx`
- `frontend/src/views/settings/components/RulesSection.tsx` — основной компонент секции
- Встроен в `frontend/src/views/settings/Page.tsx` после блока с биржами

### Структура компонента

1. **Форма добавления правила:**
   - `Select` для выбора метрики (только доступные, без уже объявленных)
   - При выборе метрики автоматически подставляются `defaultThreshold` и `defaultOperator` из каталога
   - `Seg` для выбора оператора (`lte` / `gte`)
   - `Input` для ввода порога с отображением единицы измерения
   - `Button` для сохранения

2. **Список объявленных правил:**
   - Каждое правило показывается в `Lookup` через `KeyValue`
   - Для каждого правила: подпись метрики, оператор, порог с единицей
   - Переключатель активности (кнопка с `aria-pressed`)
   - Кнопка удаления
   - Правила с неизвестной метрикой (отсутствуют в каталоге) показываются выключенными (opacity 0.6) с подписью `unknownMetric` и кнопкой удаления

3. **Состояния:**
   - `Skeleton` при загрузке
   - `ErrorNote` при ошибке
   - `EmptyState` когда правил нет

## Ревью и исправление дефектов

### Finding 1 (Critical) — ошибка удаления не показывается

**Проблема:** `handleDelete` вызывает `deleteRule.mutate(metric)`, но `deleteRule.error` нигде не отрисовывается. При отказе сервера правило визуально останется на месте, пользователь не получит объяснения и будет нажимать ещё раз.

**Исправление:** Добавлена `ErrorNote` для `deleteRule.error` рядом со списком правил (после заголовка `overviewTitle`).

```tsx
<ErrorNote error={deleteRule.error} fallback={t('settingsTitle')} />
```

### Finding 2 (Important) — кнопка сохранения не показывает состояние ожидания

**Проблема:** Строка с кнопкой сохранения: `{upsert.isPending ? t('save') : t('save')}`. Обе ветки одинаковые — пользователь не понимает, идёт ли запрос.

**Исправление:**
1. Добавлены новые ключи локализации в `ru.json` и `en.json`:
   - `"saving": "Сохранение…"` (русский)
   - `"saving": "Saving…"` (английский)
2. Обновлена кнопка:
   ```tsx
   {upsert.isPending ? t('saving') : t('save')}
   ```

### Finding 3 (Important) — удаление одного правила блокирует все остальные

**Проблема:** `const isDisabled = isUnknown || deleteRule.isPending` вычисляется для каждой строки, но `deleteRule.isPending` — общее состояние. Пока удаляется одно правило, у всех остальных гаснут кнопки.

**Исправление:** Блокировка по конкретному правилу через сравнение `deleteRule.variables` (который содержит метрику удаляемого правила):

```tsx
const isDeleting = deleteRule.isPending && deleteRule.variables === rule.metric;
```

Теперь:
- Переключатель активности отключается только при удалении конкретного правила (`disabled={isDeleting}`)
- Кнопка удаления отключается при удалении этого правила или если метрика неизвестна (`disabled={isDeleting || isDisabled}`)
- Соседние строки остаются активными
